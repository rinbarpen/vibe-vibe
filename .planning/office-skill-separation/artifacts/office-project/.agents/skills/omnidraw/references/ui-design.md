# Omnidraw 的 UI 设计约束

用于新图、重绘、图解网页、仪表盘及其他可视化路线；分流时将适用要求交给实际制作技能，交付前复核。
规则来自 vibe-coding 的 `rules/vibe-coding-ui-design.mdc` 与 `references/ui-usability.md`；在本源码仓库位于 `manifests/vibe-coding/`。本文件是随技能分发的绘图适配，不依赖源码仓库相对路径或另装 UI 技能。目标项目已有设计系统、venue 规范及用户明确的格式约定优先；复用其可用规则，并应用下列与媒介相符的要求。

## 先确定要让人看懂什么

- 从现有请求提取读者、主要任务、关键结论与交付媒介。信息已确认时直接沿用，不为视觉修改重新索要选题或数据。
- 关键关系、状态、异常与证据边界立即可见；来源、历史和支持细节按需查看。静态图可用附页、题注或源文件承接细节，关键失败与限制仍留在相关位置。
- 用位置、对齐、分组、字号和间距表达层级；不默认把阶段、指标或领域全部做成等权卡片，也不通过缩小字体或制造无效留白换取简洁。

## 文案克制而不丢失含义

**Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.**

- 不给每个节点、卡片或分组例行补问题句、口号、双语副标题或重复说明；每条次要文案应提供当前任务需要的新信息。
- 保留必要标签、图例、单位、来源、风险、限定条件及替代文本；重复信息合并，科学关系、数据和支持范围不因美化改变。
- 模型生成的图内文字先限定到实际需要的标签，不用伪文字或装饰性小字填充空白。

## 统一视觉语言

- 颜色、字阶、间距、线型和圆角使用一套可复用 token；HTML 用 CSS 变量，矢量/绘图代码用集中配置，不在组件中散布调色板。
- 颜色表达含义，不作为唯一识别方式；普通文字对比度至少 4.5:1，大字至少 3:1。状态同时提供文字、形状或线型差异。
- 优先用层级和留白分组，卡片仅在真实分组或边界需要时使用；不套默认渐变、无意义动效和整齐却无语义的卡片阵列。

## 按交付媒介验收

| 媒介 | 必须核对 |
| --- | --- |
| SVG / PNG / PDF / 论文与演示图 | 在实际嵌入尺寸检查标签、线条、对比度、裁切、遮挡和关系；保留可编辑源。Web 的 hover、加载、保存等状态不机械套用。 |
| HTML / 交互图 / 仪表盘 | 按任务重排移动布局，而非整体缩小桌面图；在 320、768、1024、1440px 检查无横向溢出、文字可读和任务可完成。检查实际存在的键盘、焦点、主题、空/错误/加载状态；动效尊重 reduced-motion。 |
| 改绘 | 保留改前版本，对照内容、信息位置和相关截图；布局变化不得掩盖失败、未接通能力或证据缺口。 |

实际渲染或操作后记录命令、尺寸/视口、观察、结果与证据。用 `PASS`、`FAIL`、`NOT RUN` 或 `N/A` 区分通过、未运行和不适用；静态阅读不替代交互验收，AI 走查不等于用户研究。问题返回所选制作路线修复，不以增加说明文字代替布局修正。
