# 多引擎游戏设计 Manifest

## 目标
创建可通过 vibe 发现和安装的游戏设计 manifest，以统一设计流程和按引擎加载的适配器覆盖主流游戏开发工具；复用既有 Unity 资源而不迁移旧模板。

## 阶段
- [complete] 1. 盘点安装契约、现有游戏资源和官方引擎资料
- [complete] 2. 定义设计产物、引擎覆盖矩阵、适配协议和人机决策边界
- [complete] 3. 实现 manifest、适配资料、初始化器和可复现工作流图
- [complete] 4. 验证发现/安装/适配/图漂移/已有项目保护及回归
- [complete] 5. 整理交付路径、验证证据和可执行回滚

## 决策与约束
- 不默认选择引擎；已存在项目以其引擎与版本为准。
- 游戏设计不是只搭工程：必须覆盖玩法、关卡、数值、叙事、美术音频、可访问性、测试和发布。
- 用统一核心协议配合具备具体实现与验证差异的引擎适配器，不承诺本机未运行的引擎构建结果。
- 保留既有 unity-game 与 CLI 公共行为，安装器仅负责本模板资源。
- 规划文件采用仓库既有 .planning/<task> 布局，隔离已完成的其他任务。

### 本轮边界
- 上一版是引擎横向适配；本轮补类型×专业任务×工具链×引擎的完整矩阵。
- 复用Unity canonical DCC脚本，由安装器分发独立可用payload并记录来源hash，不维护第二份源。
- Git/LFS/Perforce策略须符合项目现状；只读检查不初始化、不改远端、不自动提交或推送。
- 旧状态文件保留，新增配置字段可选；新的运行时行为仅在有真实结果时登记。
