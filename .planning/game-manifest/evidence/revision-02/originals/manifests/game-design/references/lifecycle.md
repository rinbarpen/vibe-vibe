# 游戏设计 → 制作：阶段与决策契约

## 总规则

- 默认 design-only：设计包审查、人工方向确认后交付；implementation：继续原型到运营。每阶段记录 owner、输入、产物、revision、验收、证据与 resume。未完成上一阶段门不声称后续完成。
- 角色职责：设计负责人主导体验与范围；引擎实现者负责映射与代码/Editor 操作；内容作者负责关卡/叙事/视听；QA 验证行为；审查者检查需求证据；人负责新增取舍、切片放行、对外发布。角色不要求生成独立代理。
- 技术不确定性先调研、最小实验、测试并形成 ADR；同一问题三轮有证据的修复仍失败且需改变约定时，提交选项、成本与推荐给人，不把普通调试整体交还。
- state/status.md 是当前事实；diagram 只是规则。engine JSON 的 not_run 不随模板测试自动变 pass。

## 阶段表

| 阶段 | 输入/执行职责 | 交付与验收 | 失败/通过后去向 |
|---|---|---|---|
| discover | 设计负责人恢复资料/工程，收敛玩家、题材、支柱、核心循环、约束 | brief 含可验证成功标准、must/should/cut、风险、未定项；竞品判断带来源与日期 | 缺技术事实由 AI 调研；有方向冲突走人工方向门 |
| engine-fit | 引擎实现者检测现有项目；新项目比较 2–3 项 | engine-decision 比较平台/输入、内容管线、性能、团队、许可/成本；选定版本/SDK 与首个验证命令 | 已有项目不重选；迁移必须另立人工决策 |
| design | 设计与内容职责展开系统、数值、关卡、叙事、UI/视听；引擎实现者写 TDD | GDD 定义操作→反馈→目标→失败/重试；至少一条完整关卡/节拍；每条 REQ-ID 连到用例；TDD 绑定所选引擎与性能预算 | 审查缺漏回 design；设计包齐备进入方向门 |
| direction-gate | AI 汇总设计包和未定项；人确认方向/引擎/模式/预算 | 显式记录 revision、决定、约束及 resume；未回复 waiting_human | 调整回 design/engine-fit；design-only 同意即交付，implementation 同意进入 prototype |
| prototype | 引擎实现者用占位资源验证最小玩法闭环与最大技术/体验风险 | 可启动入口、完成一次核心循环、胜负/失败/重试；实际输入/日志和试玩观察；真人体验反馈独立 | 行为失败回 prototype，需改核心支柱回方向门 |
| vertical-slice | 内容+实现制作一个代表性切片，串通资产/工具/存档/构建 | 目标品质片段、资源预算、目标设备帧时、真实包、风险/工期更新 | AI QA 失败回 owner；通过后人工决定扩量/缩减/停止 |
| slice-gate | 人判断切片是否支撑规模化制作 | 记录包 hash、设计 revision、成本、余留风险和生产范围 | 放行→production；调整→prototype；未答复等待 |
| production | 按功能/内容批次单写者实现；QA 逐批回归 | 覆盖 must 需求、可追踪资源许可、里程碑状态；变更走差异评审 | 在既定目标内返工；新预算/平台/引擎变更走 change-gate |
| qa | Alpha 功能完整；Beta 平衡、性能、兼容、本地化/可访问性；发布审查 | 原用例复测+相邻回归；目标设备/多人/存档迁移；缺陷分级、构建/试玩/真人反馈分开；未测项显式记账 | 失败回 production；依赖缺失先环境等待；通过生成候选包 |
| release-gate | AI 汇总候选包、商店素材、许可、隐私、迁移、回退；人决定对外发布 | 批准绑定目标平台/受众、包 hash、设计 revision；无阻断缺陷或明确接受风险 | 同意→release/live；退回→production；未答复等待 |
| release/live | AI 在批准范围执行发布/监测并保留回退点 | 发布记录、存档/配置兼容、崩溃与反馈指标、热修复/复盘；不伪造平台批准 | 异常→rollback，再进入 QA；新增体验目标→discover/design |

## 跨阶段分支

### 技术返工与依赖等待

技术失败由原 owner 修复，QA 重跑原测试。缺 Editor/SDK/设备/连接则记 `waiting_dependency`、阻断原因、所需工具与恢复用例；AI 可先完成不受阻的设计/纯逻辑任务。环境就绪后 AI 在原验收点续跑，不以未运行填通过。依赖选择需要新增付费或平台取舍时进入 change-gate。

### 高影响变更门

触发：改核心支柱/平台/联网或商业化；切换引擎、升级大版本；引入付费或云服务；超预算；破坏旧存档；对外可见操作。AI 提交 delta、受影响需求、成本与回退；人可同意、调整或暂停。同意后 AI 从受影响的 design/engine-fit 恢复；调整返回原方案；未答复继续等待，暂停保持状态不丢弃产物。

### 回退

每次有状态修改前保留分支/commit/资产快照、平台版本和存档样本；不要将代码回退当成云数据回退。候选包或上线异常先在约定权限内停止扩大影响，按 production-release 中的步骤恢复已验证版本/配置；不可逆存档迁移须事前决策。回退后进入 QA 验证恢复行为，再决定是否重发；模板图不表示已经执行回退。

## 最小证据

`REQ-ID → 设计段落/数值行 → 实现路径/资源 ID → TEST-ID → 构建/设备/输入/结果/日志或截图`。证据可标 pass/fail/not_run，不允许将 not_run 隐藏在通过总数内。真人试玩记录受试者范围与观察，不把 AI 自动操作称作真人反馈。自审和独立审查各自具名，缺独立 reviewer 要显式记录。
