# Unity 垂直切片审查

## 工作位置与证据

先识别实际 Unity 项目、用户指定范围和既有产物。存在 `.unity-game/` 时读取相关状态，实际文档放 `.unity-game/deliverables/`，按需复用已存在的 templates；独立安装时使用用户指定目录，默认 `docs/unity-game/`，沿用项目现有测试和构建工具。只有实际存在时才调用 `.unity-game/scripts/unity_cli.py`，先查看其 `--help`。缺 Editor 或设备时仍可交付静态产物，但对应运行验收记 `not_run`，附具体阻塞与复现步骤；`passed` 必须有真实证据。

同一 Scene、Prefab、Animator、材质等序列化资源及其 `.meta` 只设一个写入者；同一工程的 Editor 导入、测试、场景编辑和构建串行。独立代码/规格任务可并行，依赖冻结后再集成。由 Editor 生成 `.meta`，移动时资源与 `.meta` 成对保留，不编造 GUID。已有版本和包先沿用，升级另行决策。

## 输入与审查独立性

取得固定源码版本、目标构建、验收表、目标硬件/预算、GDD/TDD 和已知限制。与切片实现者使用独立审查上下文；没有独立执行者时如实标记自查。冻结被审版本，避免对着不断变化的 Editor 工程给批准结论。

## 操作

1. 从构建启动说明复现核心流程、失败重试、退出重进与关键存档；记录真实构建来源、设备、操作与结果。说明文档或截图不代替可操作构建。
2. 对照目标审查玩法清晰度、操作响应、关卡节奏、UI 可读性、动画/VFX 预警、混音与反馈同步；区分阻断问题、基线必修项和偏好建议，引用场景/对象或证据时间点。
3. 抽查资源生产链：一项新资源能否按规格进入工程，导入配置可复用，Prefab/引用可靠，许可来源可追溯；评估新增一关/一敌人的工时、依赖和瓶颈，不把一段手工打磨当成生产能力。
4. 核对目标设备性能、加载和构建日志；查看未执行测试与失败项，而非只读成功摘要。缺设备、测试日志或构建时单独列为未验证条件，不推断通过。
5. 输出决策建议：继续制作、限定条件修复后复验、回到原型调整。每项必修问题指派责任角色和复验条件；关闭问题时链接真实修复版本与再测证据。

## 输出与交接

交付 `slice-review.md`：被审版本、验收矩阵、问题证据/优先级、生产成本判断、接受风险及建议。交给 producer 汇总并向用户展示代表流程、风险和版本；全生命周期只有用户明确确认此切片基线后才启动批量制作，审查者“通过”或构建成功不替代用户确认。记录确认原话/消息引用、日期与固定产物版本。

单独请求审查时交付审查与复验待办即可；不自动修改被审内容、采购或推进发布。

## 阶段审查关系

本技能用于专项验收或准备评审材料；完整阶段最终由独立上下文的game-reviewer使用unity-game-review及相应阶段profile形成版本绑定结论。实现者准备的材料和自查不等同独立审查通过；修改由原执行skill/owner完成。
