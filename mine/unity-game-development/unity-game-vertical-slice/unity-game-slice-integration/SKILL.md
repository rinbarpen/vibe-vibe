# Unity 垂直切片集成

## 工作位置与证据

先识别实际 Unity 项目、用户指定范围和既有产物。存在 `.unity-game/` 时读取相关状态，实际文档放 `.unity-game/deliverables/`，按需复用已存在的 templates；独立安装时使用用户指定目录，默认 `docs/unity-game/`，沿用项目现有测试和构建工具。只有实际存在时才调用 `.unity-game/scripts/unity_cli.py`，先查看其 `--help`。缺 Editor 或设备时仍可交付静态产物，但对应运行验收记 `not_run`，附具体阻塞与复现步骤；`passed` 必须有真实证据。

同一 Scene、Prefab、Animator、材质等序列化资源及其 `.meta` 只设一个写入者；同一工程的 Editor 导入、测试、场景编辑和构建串行。独立代码/规格任务可并行，依赖冻结后再集成。由 Editor 生成 `.meta`，移动时资源与 `.meta` 成对保留，不编造 GUID。已有版本和包先沿用，升级另行决策。

## 输入与基线

取得原型结论、GDD/TDD、目标平台/设备、性能预算、视听规格与可用资源。选一段能代表生产难度的短流程，不选只展示最佳光照的孤立房间；覆盖核心玩法、典型敌人/障碍、UI、音频、存档边界和退出/重试。记录每项最终品质、临时占位与本次排除项。

## 操作

1. 编制切片验收表：用户可完成的步骤、内容质量、帧时间/内存预算、启动/加载、构建与已知风险；指标来自本项目目标而非通用帧率假设。
2. 将内容和工程按接口拆开：关卡锚点/尺寸、事件名、动画参数、音频触发、资源命名与加载约定。各模块在独立路径并行；Scene/Prefab/序列化配置由分配的单写者装配，Editor 串行排队。
3. 先做从源资源 → 导入设置 → Prefab → 场景 → 运行 → 目标包的完整小样，再扩大本切片内容；检查贴图压缩、材质/管线、碰撞、LOD、音频与动画的真实引用和 `.meta`。
4. 按依赖批次集成并回归，重点测正常通路和取消/重试：加载未完成、玩家死亡、暂停恢复、场景切换、存档后重进。先修流水线瓶颈再复制内容。
5. 用实际目标设备构建测帧时间分布、内存与加载；保留版本/场景/画质/设备/采样条件。Editor 数据可辅助定位，但不能替代设备预算验收。

## 输出与验收

交付可运行切片、`slice-integration.md`、资源/接口清单、实际测试/构建与性能证据、临时资产/技术债表。只有真实跑通代表流程并链接可复现产物才标记集成通过；未完成项按影响列入风险。

交给独立 `game-reviewer`、`qa-engineer` 和相关美术/音频负责人审查；只完成集成不等于生产基线已批准。全生命周期必须在切片审查后取得用户明确基线确认，再进入批量制作；单独调用本技能不强行启动其他阶段。
