# Unity Beta 真实体验与设备验收执行

## 执行边界与状态

这是执行 skill，不是角色说明：宿主实际读取本文件后，用可用工具完成下面的产物与验证。skill 名不是工具，文字“调用”不代表已执行；只有真正读入技能、委派成功或工具结果才记为执行。先识别用户请求的是完整阶段还是局部任务，只完成本次承诺，不自动跑整条生命周期。

复用既有工程版本、包、平台与已批准决策，不硬编码 Unity 版本或擅自升级。存在 `.unity-game/` 时，产物放 `.unity-game/deliverables/`，主代理单写共享 state/tasks/decisions；子代理仅写被分配的产物和证据。独立安装默认 `docs/unity-game/` 或用户指定目录；本文件含独立执行方法，不依赖其他技能或模板已安装。文档先写临时文件再原子替换。

任务单必须有任务 ID、输入修订、原执行 skill、owner、可写路径、依赖、验收与回传证据。真正具备 subagent 工具时才委派下表角色，按宿主并发上限分配不重叠文件；没有时由主代理按同一契约串行实现并如实记录。Scene、Prefab、序列化资源、项目配置及 `.meta` 单写，同工程 Editor 导入/测试/构建串行；资源与 `.meta` 成对保留。

## 输入与就绪

Alpha 结果、候选标识、目标玩家/平台设备、性能预算、体验目标、遗留缺陷与可用样本。缺预算先提出待确认口径；局部性能或平衡请求仅处理该方向。

## 专项方法与任务所有权

若阶段/整包同时安装，按当前缺口读取本执行技能父目录中的 `<下表 skill>/SKILL.md`，每个都是可选专项方法；只装本 skill 时直接执行下一节等价方法。不要求无关技能或不存在的相对链接。多角色任务拆成明确单一 owner 的子任务，不能共同抢写。

| 原执行 skill（安装时实际读取） | 建议 subagent | 本轮交付 |
|---|---|---|
| `unity-game-balance-playtest` | `playtest-analyst / systems-designer` | 试玩原始记录、样本偏差、平衡实验与计算 |
| `unity-game-performance` | `performance-engineer` | 设备采样、Profiler 证据、前后对照与回归 |
| `unity-game-compatibility` | `qa-engineer` | 设备/输入/语言/可访问性矩阵及实测 |

未安装专项 skill 时，任务单原执行 skill 记 `unity-game-beta-execute`，由对应角色按本文件方法执行；不能把未读取的专项记成已调用。

## 实际执行

1. 锁定同一候选版本和测量口径；并行设计试玩、性能路线、兼容矩阵，明确样本/设备覆盖与缺口。以低配/代表设备而不是开发机代替验收环境。
2. 真实试玩分离观察与解释，按玩家群体检查失败、选择、资源与节奏；平衡实验一次改主要变量，记录样本数、窗口、噪声和公式输入，不从个别评论直接得出总体结论。
3. 性能先复现并采样 CPU/GPU、帧尖峰、GC、内存与加载，再定位最小热点；相同设备、路线、质量和构建配置测前后，注明 Profiler 开销，回归画质和功能。
4. 目标设备实际测输入/分辨率、生命周期、存储与安装升级、文字溢出/语言、可访问性和长时稳定。修改由原模块 owner 负责，Editor 操作串行；所有阻断修复后重新跑受影响矩阵。

## 本阶段交付与推进

`beta-summary.md`、玩法实验、设备预算前后统计、原始采样索引、兼容矩阵、缺陷与回归；报告真实覆盖和偏差，未采样设备或未执行预算保持 not_run。

独立审查通过后主代理向 release 交接固定候选范围与残余风险；Beta 通过不是用户 release 确认。

## 独立 reviewer 与返工闭环

1. 冻结本次提交/文件哈希、任务单及证据，生成 `beta-execution-rN.md`：范围、任务→原执行 skill/owner、实际产物、命令/输入/字面结果/退出码、未运行项、风险、版本与回退。仅使用真实执行得到的 `passed` / `failed` / `not_run`，静态检查不替代运行。
2. 若已安装 `unity-game-review`，实际读取该技能，再由独立 `game-reviewer` 以 profile `beta` 审查本次范围和固定修订。该 skill 不存在时，在新独立 reviewer 上下文执行同样的任务验收：检查输入→产物→证据、独立复现关键检查、给 finding ID/严重度/文件与复现/原执行 skill 和 owner/验收条件，并给 `passed`、`changes_requested` 或 `blocked`。新 reviewer 不承担实现；实现者自检不冒充独立审查。宿主没有独立上下文能力时输出待审查包、注明独立审查未执行，保持阶段不推进。
3. `changes_requested` 必须携 finding ID 回到任务单记录的**原执行 skill + 原 owner**修复；不要重派 reviewer 实现或换技能掩盖问题。生成新修订，重跑受影响验证，独立 reviewer 针对新修订复审；重复返工无新证据时记录原因和待决事项，避免无界重试。
4. `blocked` 或必需运行证据 `not_run` 时，交付已完成部分和具体恢复步骤，阶段原地保持。只有独立审查 `passed` 后由主代理写阶段完成/下一步建议；完整流程还须遵守本阶段用户门。局部任务只验收本次范围，不据此宣称整个阶段通过。
