# 兼容、可访问性与本地化

## 输入与风险矩阵
读取实际支持平台/OS、最低设备、图形 API、输入设备、语言和产品可访问性承诺。按用户覆盖与故障风险挑选代表组合及边界，标明真实设备、模拟器与未覆盖组合；矩阵是支持声明的依据，不自动推导所有平台可用。

## 操作
1. 每行锁定构建哈希、OS、设备、图形配置和输入；覆盖安装/升级、启动、核心循环、保存、暂停/恢复、窗口/横竖屏、离线及项目实际依赖的网络变化。
2. 验证键鼠/手柄/触控等已支持输入的完整导航、重绑定、热插拔、焦点、提示图标和死区；不能只验证主菜单。
3. 以实际设置检查字幕、文字缩放、对比度、非颜色信号、闪烁/镜头运动选项、音量分组和操作负担。辅助技术支持以平台实际结果记录，不以静态 UI 设计保证兼容。
4. 用伪本地化和目标语言检查溢出、字体 glyph、换行、RTL（如适用）、输入法、区域日期/数字、字幕时序和关键图片文本；切语言后验证存档/场景持久化。
5. 记录复现步骤、截图/视频、设备日志和严重度；在同设备复验修复，并重跑关联输入/语言组合。平台要求变化时查目标平台官方当期文档并保存来源/日期。

## 产物、验收与交接
交付覆盖矩阵、体验设置清单、语言问题表及证据索引。各组合区分 `passed`、`failed`、`not_run`；阻断支持平台的缺陷由主代理明确处置，未测组合不标支持已验证。`qa-engineer` 汇总，`ui-ux-designer` 负责交互/可访问性，`technical-artist` 处理显示，`publishing-manager` 对齐支持声明。

## 运行约定
- 先读取现有项目约定、`ProjectSettings/ProjectVersion.txt`、包锁定文件和已确认平台；使用项目版本对应官方文档，不预设 Editor 版本或设备。
- 如存在 Unity manifest，使用 `.unity-game/` 既有任务与产物；否则将产物写入用户指定位置，未指定时使用 `docs/unity-game/`。共享阶段、任务、决策由主代理单写；子代理仅交付其认领文件和证据。
- 独立文档、测试设计可按文件所有权并行；同一工程的 Unity Editor、Scene、Prefab、序列化资源和项目配置由单一写者串行处理，资源与 `.meta` 成对提交。文档采用临时文件写入后原子替换。
- 运行结论使用 `passed`、`failed`、`not_run` 并附证据。缺少 Editor、设备或凭据时记录未执行范围；静态检查不替代真实运行。已安装辅助工具时可先读 `.unity-game/scripts/unity_cli.py --help`，否则沿用项目工具及对应版本官方文档。
