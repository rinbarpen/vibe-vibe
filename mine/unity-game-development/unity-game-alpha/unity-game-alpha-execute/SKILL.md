# Unity Alpha 功能完整验收执行

## 执行边界与状态

这是执行 skill，不是角色说明：宿主实际读取本文件后，用可用工具完成下面的产物与验证。skill 名不是工具，文字“调用”不代表已执行；只有真正读入技能、委派成功或工具结果才记为执行。先识别用户请求的是完整阶段还是局部任务，只完成本次承诺，不自动跑整条生命周期。

复用既有工程版本、包、平台与已批准决策，不硬编码 Unity 版本或擅自升级。存在 `.unity-game/` 时，产物放 `.unity-game/deliverables/`，主代理单写共享 state/tasks/decisions；子代理仅写被分配的产物和证据。独立安装默认 `docs/unity-game/` 或用户指定目录；本文件含独立执行方法，不依赖其他技能或模板已安装。文档先写临时文件再原子替换。

任务单必须有任务 ID、输入修订、原执行 skill、owner、可写路径、依赖、验收与回传证据。真正具备 subagent 工具时才委派下表角色，按宿主并发上限分配不重叠文件；没有时由主代理按同一契约串行实现并如实记录。Scene、Prefab、序列化资源、项目配置及 `.meta` 单写，同工程 Editor 导入/测试/构建串行；资源与 `.meta` 成对保留。

## 输入与就绪

已集成功能、需求/主流程、候选提交、存档 schema 与受支持旧版本、目标平台和现存缺陷。局部测试请求按相应功能范围验收，不因一个测试任务启动全游戏 Alpha。

## 专项方法与任务所有权

若阶段/整包同时安装，按当前缺口读取本执行技能父目录中的 `<下表 skill>/SKILL.md`，每个都是可选专项方法；只装本 skill 时直接执行下一节等价方法。不要求无关技能或不存在的相对链接。多角色任务拆成明确单一 owner 的子任务，不能共同抢写。

| 原执行 skill（安装时实际读取） | 建议 subagent | 本轮交付 |
|---|---|---|
| `unity-game-test-automation` | `qa-engineer` | 自动测试代码、执行命令、XML/日志与覆盖矩阵 |
| `unity-game-flow-regression` | `qa-engineer` | 流程/存档样本、迁移差异及缺陷复现 |

未安装专项 skill 时，任务单原执行 skill 记 `unity-game-alpha-execute`，由对应角色按本文件方法执行；不能把未读取的专项记成已调用。

## 实际执行

1. 从功能清单构建需求→场景→测试→证据矩阵，定义关键路径与阻断级别。区分纯逻辑、Unity 生命周期、人工/设备验证，避免零测试或只编译被写成已通过。
2. 让 QA 编制并实现测试，玩法角色负责独立文件中的最小缺陷修复。冻结输入/种子与候选标识后，串行执行 EditMode 和 PlayMode；保存命令、原始 XML、日志及退出码。
3. 使用隔离数据从新游戏完成关键流程、结算、退出重进和重开；在关键进度保存/恢复，验证重复循环的奖励、解锁与状态。需要的中断写入、无效数据、低空间等按实际实现测试。
4. 对受支持旧版样本先保存只读原件及哈希，再升级迁移并比较字段、默认值、进度与资源守恒；验证迁移重跑。每个缺陷记录最小输入、候选版本、复现和修复后回归证据。

## 本阶段交付与推进

功能验收矩阵、EditMode/PlayMode 原始结果、完整流程报告、存档样本与迁移差异、分级缺陷及 `alpha-summary.md`；主流程阻断、进度损坏或必需测试 not_run 时保留 Alpha 待验。

独立审查确认关键路径和数据兼容通过后由主代理交接 beta，列明被接受且非阻断的遗留项；不增加第四个用户阶段确认门。

## 独立 reviewer 与返工闭环

1. 冻结本次提交/文件哈希、任务单及证据，生成 `alpha-execution-rN.md`：范围、任务→原执行 skill/owner、实际产物、命令/输入/字面结果/退出码、未运行项、风险、版本与回退。仅使用真实执行得到的 `passed` / `failed` / `not_run`，静态检查不替代运行。
2. 若已安装 `unity-game-review`，实际读取该技能，再由独立 `game-reviewer` 以 profile `alpha` 审查本次范围和固定修订。该 skill 不存在时，在新独立 reviewer 上下文执行同样的任务验收：检查输入→产物→证据、独立复现关键检查、给 finding ID/严重度/文件与复现/原执行 skill 和 owner/验收条件，并给 `passed`、`changes_requested` 或 `blocked`。新 reviewer 不承担实现；实现者自检不冒充独立审查。宿主没有独立上下文能力时输出待审查包、注明独立审查未执行，保持阶段不推进。
3. `changes_requested` 必须携 finding ID 回到任务单记录的**原执行 skill + 原 owner**修复；不要重派 reviewer 实现或换技能掩盖问题。生成新修订，重跑受影响验证，独立 reviewer 针对新修订复审；重复返工无新证据时记录原因和待决事项，避免无界重试。
4. `blocked` 或必需运行证据 `not_run` 时，交付已完成部分和具体恢复步骤，阶段原地保持。只有独立审查 `passed` 后由主代理写阶段完成/下一步建议；完整流程还须遵守本阶段用户门。局部任务只验收本次范围，不据此宣称整个阶段通过。

## 实际游戏测试任务包

有实际可玩版本时派发unity-game-testing及当前子技能，普通玩家输入、前置状态、可观察断言、游戏/构建哈希、录屏截图与日志交叉记录。只编译、看Scene或编辑内部变量不记正常游玩通过；缺输入/窗口/设备时not_run。测试执行者与原实现者分离，测试报告由独立game-reviewer用unity-game-test-review审查，再走Alpha阶段总审。
