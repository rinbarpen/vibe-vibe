# 修复复验与回归

由 `qa-engineer` 执行；原功能 owner 修复实现，独立 `game-reviewer` 审查结论。此技能独立可用。

## 操作

1. 读取原缺陷、最小复现、原始日志/截图、预期、修复说明和实际差异；记录修复前后构建 SHA-256、源码 revision/dirty 哈希、Unity/包/平台版本及输入/存档格式。确认被测二进制确实来自当前修复版本，不能只写 Git HEAD。
2. 在两个隔离实例/独立用户数据目录准备同种子和同初始测试数据，原存档/真实账号不变。检查实际已连接 MCP schema、项目 harness 或已安装 GUI skill；WebGL 使用现有浏览器 skill 操作真实 canvas。未经确认不进行联网、凭据、付费与外部动作。记录工具/skill 路径、版本、环境和恢复方法。
3. 可用时先在原构建跑原序列确认基线失败，再在修复构建执行相同步骤；原版本缺失时可复用来源清晰的原始失败证据并明确未现场重跑。没有可靠原失败证据时只记录“当前版本观察”，不能声称验证了由失败到通过的转变。
4. 用正常输入测试原路径，保存实际调用/参数、输入按下/保持时长/释放、时间戳、expected/actual、画面和日志。状态注入若原复现已依赖则保留条件并单列正常输入覆盖，不临时跳过出错流程。用有限重复测试原波动条件，完整保留每个 attempt，不用单次偶然成功关闭问题。
5. 根据修复差异选最小受影响回归：相关边界、失败与重试、暂停/重载、临时存档兼容、相邻功能或平台差异。自动 EditMode/PlayMode 结果单列，项目有真实测试命令时运行并保存命令/退出码/XML；测试绿灯不替代原游戏输入路径的复验。
6. 在时间/动作/重试预算内完成，异常或结束释放全部已按输入，恢复临时数据并记录结果。若发现新回归，保存独立问题并返回 owner；不要自己改实现、降低断言或更新视觉基线来获得通过。

## 判定与输出

逐项用 `passed` / `failed` / `not_run`：原预期和必需回归实际满足才复验 `passed`；原缺陷仍在或引入确定回归为 `failed`；缺构建/设备/输入通道/可靠必需证据为 `not_run`。另记问题候选状态 `verified_fixed` / `still_reproduced` / `inconclusive`；主代理依据独立审查决定是否关闭，不让报告改写共享问题状态。

报告包含 bug ID、原/新版本与哈希、原始失败证据、实际前后命令/输入/输出/退出、重复次数、回归列表、截图与日志时间戳、未测条件、清理结果、owner 与后续验收条件。无音频、Profiler、目标设备或人工玩家时对应检查保持 `not_run`。写 producer 指定 `.unity-game/deliverables/testing/<run-id>/`，独立默认 `docs/unity-game/testing/<run-id>/` 或用户指定目录；保存重读并回传 SHA-256，交独立 reviewer。
