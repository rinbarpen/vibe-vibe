# 实际画面与视觉回归

`qa-engineer` 执行；`ui-ux-designer` / `art-director` 解释冻结设计标准，不由实现者自行批准基线变化。此技能独立可用，不要求父技能文件。

## 操作

1. 收集本轮验收场景、设计参照、已有认可截图、变更原因和目标分辨率/宽高比/安全区/语言/字号/输入方式。记录构建与源码哈希、Unity/渲染管线/画质版本、平台/设备/GPU、实际 viewport、缩放、seed、相机和时间条件；只覆盖项目要求的组合。
2. 用隔离构建和临时存档启动，原用户数据保持原样。发现已连接 MCP 的实际工具/schema、现有 harness 或已安装 GUI skill；WebGL 读取浏览器 skill 并操作真实 canvas。MCP 截取 Editor Scene 视图不自动等价于 Game View 或发布包画面；截图必须注明来源。
3. 通过正常输入到达目标画面，记录工具/skill 路径、调用参数、动作与按键保持/释放时长、时间戳、预期/实际和截图。需要固定相机/动画帧或状态注入时记录其设置方法与影响，作为视觉夹具，不将该捷径计入正常流程输入覆盖。缺渲染或截图能力时相应检查 `not_run`。
4. 按场景检查遮挡、裁切、对齐、层级/焦点状态、对比度/不只依赖颜色的提示、文字与本地化溢出、控制提示、世界/屏幕 UI、材质/光照、LOD/闪烁等本轮风险。静态截图看不出的问题使用实际连续采集或视频；不能从单帧推断动画流畅、声音或性能。
5. 有认可基线时对同条件画面比较，先确认尺寸、相机、状态、画质和基线 revision；冻结阈值/遮罩及理由，保留原图和差异图。无比较工具就做有标注的视觉检查，别虚报像素统计；不通过重采新基线消除差异。随机粒子、TAA 等非确定区域单列，不用宽阈值掩盖真实回归。
6. 单实例输入串行；达到预算或中断时释放输入、退出测试实例并核对临时数据恢复。网络、真实账号、凭据或付费动作另行确认。

## 交付与判定

每个组合记录需求/基线版本、截图来源与时间戳、实际条件、操作、expected/actual、原图/差异图和 SHA-256、问题位置（坐标/元素/场景）、严重度、owner、未执行项。已观察视觉偏差为 `failed`，满足验收为 `passed`，缺工具/设备/认可基线导致的比较缺口为 `not_run`；无基线时可完成明确标准的检查，但不得声称回归对比通过。

输出在 producer 指定 `.unity-game/deliverables/testing/<run-id>/`，独立默认 `docs/unity-game/testing/<run-id>/` 或指定目录。报告保存后重读并哈希；UI 问题交对应 UI owner，材质/画面问题交美术或技术美术 owner，逻辑状态问题交原功能 owner，修复后重新采同条件画面。独立 reviewer 只认可被审 revision，不自行批准艺术方向或用户门。
