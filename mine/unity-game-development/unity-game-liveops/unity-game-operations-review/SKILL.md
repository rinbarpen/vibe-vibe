# 运营复盘与迭代决策

## 输入与指标契约
读取发布/事件时间线、反馈队列、遥测 schema、隐私选择、商业模式和既定目标。先定义每个指标的事件、单位、分子/分母、去重键、时区、观察窗口、用户/会话口径及 cohort；安装、活跃、回访和付费不能混用分母。

## 操作
1. 审核数据延迟、缺失、重复、时钟与版本分布；区分同意采集用户和全体玩家，解释离线、拒绝采集及平台限制的偏差。不为补齐分析静默增加跟踪。
2. 结合崩溃/存档事故、留存/完成率、体验反馈及项目选择的商业指标，设置健康护栏；隐私敏感内容不写原始日志或公开复盘，按既定权限/保留周期处理。
3. 按版本、渠道、设备和熟练度分层，说明样本与区间；区分发布影响、营销带量、季节性及同期变更。观察相关性不直接宣称因果，小 cohort 防止身份暴露。
4. 对变化列出有证据的解释与竞争假设，结合试玩/故障复现核验；为下一轮提出优先级、预期收益、成本、风险和最小实验，预定义主要指标、护栏、观测窗口及停止条件。
5. 实验结束按原口径复盘；无效/负向结果保留，版本差异可追溯。采购、外部活动、埋点扩展和实际发版先取得相应操作确认。

## 产物、验收与交接
交付指标字典、数据质量/隐私说明、带来源的分层复盘、结论置信度及下一轮实验任务。无足够数据时交付采集/验证计划并标注 `not_run`，不编造增长。`playtest-analyst` 审证据，`publishing-manager` 核渠道背景，`game-designer` 提体验实验，`game-producer` 决定路线与共享计划。

## 运行约定
- 先读取现有项目约定、`ProjectSettings/ProjectVersion.txt`、包锁定文件和已确认平台；使用项目版本对应官方文档，不预设 Editor 版本或设备。
- 如存在 Unity manifest，使用 `.unity-game/` 既有任务与产物；否则将产物写入用户指定位置，未指定时使用 `docs/unity-game/`。共享阶段、任务、决策由主代理单写；子代理仅交付其认领文件和证据。
- 独立文档、测试设计可按文件所有权并行；同一工程的 Unity Editor、Scene、Prefab、序列化资源和项目配置由单一写者串行处理，资源与 `.meta` 成对提交。文档采用临时文件写入后原子替换。
- 运行结论使用 `passed`、`failed`、`not_run` 并附证据。缺少 Editor、设备或凭据时记录未执行范围；静态检查不替代真实运行。已安装辅助工具时可先读 `.unity-game/scripts/unity_cli.py --help`，否则沿用项目工具及对应版本官方文档。
