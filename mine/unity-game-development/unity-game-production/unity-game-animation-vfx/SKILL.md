# Unity 动画与 VFX

## 工作位置与证据

先识别实际 Unity 项目、用户指定范围和既有产物。存在 `.unity-game/` 时读取相关状态，实际文档放 `.unity-game/deliverables/`，按需复用已存在的 templates；独立安装时使用用户指定目录，默认 `docs/unity-game/`，沿用项目现有测试和构建工具。只有实际存在时才调用 `.unity-game/scripts/unity_cli.py`，先查看其 `--help`。缺 Editor 或设备时仍可交付静态产物，但对应运行验收记 `not_run`，附具体阻塞与复现步骤；`passed` 必须有真实证据。

同一 Scene、Prefab、Animator、材质等序列化资源及其 `.meta` 只设一个写入者；同一工程的 Editor 导入、测试、场景编辑和构建串行。独立代码/规格任务可并行，依赖冻结后再集成。由 Editor 生成 `.meta`，移动时资源与 `.meta` 成对保留，不编造 GUID。已有版本和包先沿用，升级另行决策。

## 输入与表现契约

取得动作/效果清单、源 rig 或 2D 动画方案、玩法时序、艺术规格与目标性能预算。区分纯装饰效果和传递玩法信息的预警、命中、无敌窗口；伤害/判定以明确的玩法逻辑为事实源，避免仅靠不可靠的表现回调改变核心规则。

## 操作

1. 冻结每个动作/特效的触发事件、打断条件、持续时间、循环/退出、优先级和资源路径；先检查既有 Animator 参数、timeline 或 VFX 系统，不擅自替换动画技术栈。
2. 实际制作或获取源 clip/粒子/贴图并记录来源。导入动画时检查 avatar/rig、单位、root motion 策略、loop 与事件时间；导入特效检查管线支持、材质混合和透明 overdraw。
3. Animator/Prefab/材质与 `.meta` 分配唯一写入者；用最小组合验证参数、过渡条件和重复触发。root motion 与脚本移动谁负责位移必须唯一明确，避免双重移动。
4. 检查中断与清理：受击打断、死亡、场景卸载、对象池复用、暂停、时间缩放、取消技能。停止粒子/音效并归还实例，避免禁用后残留、事件重复或动画卡死。
5. 在真实战斗密度与相机距离下验证可读性、命中同步、预警时长、闪烁强度及遮挡；测粒子峰值、透明成本与分配/池容量，保留目标设备条件。Editor 预览不代表实机效果和成本已通过。

## 输出与验收

交付真实源资源、clips/controllers/VFX/Prefab 与 `.meta`、`animation-vfx.md` 事件表和证据。验收包含动作/特效正常及中断路径、玩法同步、批量触发成本和资源回收。仅有动效描述/提示词时记为规格完成，不记资产或运行验收通过。

交给 `gameplay-programmer` 对齐判定时序，`technical-artist` 核性能，`qa-engineer` 复验取消/死亡/池复用；共享场景由指定集成人员最终装配。
