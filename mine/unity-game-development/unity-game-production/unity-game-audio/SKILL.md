# Unity 音频制作与集成

## 工作位置与证据

先识别实际 Unity 项目、用户指定范围和既有产物。存在 `.unity-game/` 时读取相关状态，实际文档放 `.unity-game/deliverables/`，按需复用已存在的 templates；独立安装时使用用户指定目录，默认 `docs/unity-game/`，沿用项目现有测试和构建工具。只有实际存在时才调用 `.unity-game/scripts/unity_cli.py`，先查看其 `--help`。缺 Editor 或设备时仍可交付静态产物，但对应运行验收记 `not_run`，附具体阻塞与复现步骤；`passed` 必须有真实证据。

同一 Scene、Prefab、Animator、材质等序列化资源及其 `.meta` 只设一个写入者；同一工程的 Editor 导入、测试、场景编辑和构建串行。独立代码/规格任务可并行，依赖冻结后再集成。由 Editor 生成 `.meta`，移动时资源与 `.meta` 成对保留，不编造 GUID。已有版本和包先沿用，升级另行决策。

## 输入与声音规格

取得音频事件清单、游戏节奏/情绪、目标平台、响度方向、空间化和无障碍需求。先检查项目的 AudioMixer、AudioSource、第三方音频中间件及许可，不为本技能自动引入中间件或更换音频栈。

## 操作

1. 建立 cue 表：事件、素材来源、时长/循环、音量/随机变化、2D/3D、优先级、并发限制、Mixer bus 和停止条件；关键反馈考虑字幕/视觉替代，不能只通过音色区分必要状态。
2. 实际录制、合成或获取素材，保留可编辑源和许可/取得日期；生成提示词或下载候选表不等于声音交付。剪掉意外静音、点击和削波，制作可听的循环点及必要淡入淡出。
3. Editor 串行导入，检查压缩、load type、平台覆盖、采样率和 mono/空间用途；长音乐与短高频音效按内存/解码成本分别决策，不统一套用设置。由 Editor 生成 `.meta`。
4. 接入事件、Mixer bus、音量设置和暂停/场景切换规则；AudioMixer、Prefab、序列化资源各有单写者。避免 Update 每帧重播，处理对象池、重复事件、同声密集触发和失效引用。
5. 用实际游戏流程试听正常、最密集战斗、暂停/恢复、死亡重试、切场景与静音设置持久化；检查循环接缝、音乐切换、重要预警可辨认性、空间衰减、声音数量和目标设备解码/内存。

## 输出与验收

交付实际源/导出音频、Unity 导入素材和 `.meta`、`audio-integration.md` cue/来源/混音表以及真实试听/设备记录。通过需要资源真实可播放、事件触发/停止正确、设置可用且成本符合项目预算；无听音或设备条件时对应验收记 `not_run`，不声称混音或循环已通过。

交给 `gameplay-programmer`/场景集成人员核对事件，`ui-ux-designer` 检查设置和替代反馈，`qa-engineer` 复验全流程，producer 追踪许可与缺口。
