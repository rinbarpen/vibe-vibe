# Unity 功能交付

## 工作位置与证据

先识别实际 Unity 项目、用户指定范围和既有产物。存在 `.unity-game/` 时读取相关状态，实际文档放 `.unity-game/deliverables/`，按需复用已存在的 templates；独立安装时使用用户指定目录，默认 `docs/unity-game/`，沿用项目现有测试和构建工具。只有实际存在时才调用 `.unity-game/scripts/unity_cli.py`，先查看其 `--help`。缺 Editor 或设备时仍可交付静态产物，但对应运行验收记 `not_run`，附具体阻塞与复现步骤；`passed` 必须有真实证据。

同一 Scene、Prefab、Animator、材质等序列化资源及其 `.meta` 只设一个写入者；同一工程的 Editor 导入、测试、场景编辑和构建串行。独立代码/规格任务可并行，依赖冻结后再集成。由 Editor 生成 `.meta`，移动时资源与 `.meta` 成对保留，不编造 GUID。已有版本和包先沿用，升级另行决策。

## 输入与边界

取得已批准设计/接口、当前项目、具体功能和可观察验收场景。全生命周期中的批量制作先核对切片用户基线已确认；单独请求一个功能时只做该功能，不强迫运行完整流程。澄清影响存档、平台输入、多人协议或付费行为的关键歧义，保留现有兼容约定。

## 操作

1. 用“前置状态 → 玩家动作/事件 → 预期状态及反馈”描述验收。搜索现有实现和调用者，明确纯逻辑、MonoBehaviour 适配、数据配置、UI/视听与存档边界，不叠建第二套框架。
2. 冻结最小接口和数据契约后，按独立模块派发 gameplay、UI、工具或 QA 任务；任务包注明可写路径、只读依赖和回传测试。共享配置、Scene/Prefab 及相关 `.meta` 单写，Editor 操作串行。
3. 最小闭环实现后逐步增加分支；显式处理进入/退出、重复事件、对象禁用/销毁、场景重载、暂停和取消。存档变更按项目既有版本约定迁移并保留样本，不静默破坏旧档。
4. 用 EditMode 覆盖状态/边界规则，用 PlayMode 验证生命周期、Unity 引用和交互；用真实目标平台烟测输入、文件访问等平台差异。失败给可复现输入，零测试与仅编译独立记录。
5. 集成前审查 diff、资源引用和缺失脚本；在干净启动及已有进度状态分别回归。对性能热点按实际数据定位，不为未经测量的问题引入大框架。

## 输出与验收

交付实际修改、`feature-NAME.md`、验收表、执行命令/结果、已知限制和回退方式；回退涉及数据变更时单独说明兼容风险。通过条件是每个承诺场景有真实结果，新增和现有关键流程均回归，缺陷交接清晰。

交给独立 `game-reviewer` 审查，`qa-engineer` 复验，producer 集成并更新共享状态。子代理只回传状态建议，不抢写 `.unity-game/state/`。
