# DCC 模型制作

## 输入与操作入口

接收模型 ID、冻结设计/多视图、尺寸/朝向/pivot、网格/材质/LOD/碰撞预算、源文件和允许修改对象。`model-artist` 单写源场景。用户选择软件优先：实际已连接 MCP 先发现工具与 schema，或读取真实存在的软件 skill，再选软件已安装 CLI/API；工具缺失时明确制作 `not_run`，不自动安装/连接/上传。

读取当前文件、对象和未保存状态；先保存/复制原件，在任务副本完成一次小操作并核对对象，再继续。保存前记录原件哈希和恢复路径，不直接覆盖用户未保存场景。每个源场景一名写入者，其他模型可分文件并行。

## 实作

1. 创建或修改真实 blockout：命名对象/集合，用设计尺寸校准比例、支撑面与 pivot；从游戏相机检查轮廓、模块接口与可交互空间，保存实际预览。粗模先过方向检查再投入细节。
2. 按需求选低模直建或高模→重拓扑；变形区安排可控边流，静态道具不强制角色式拓扑。检查重复点、退化面、内部隐藏面、非预期孔洞、自交和破坏着色的细长三角形；开放面/非流形如有意设计须注明用途。
3. 校验法线朝向、镜像后的 winding、硬/软边及切线约定；按最终导出策略验证三角化结果而非只看 DCC 四边面统计。变换应用由软件和绑定状态决定，不对已有骨架盲目 apply transforms。
4. 按真实视距制作 LOD 并检查轮廓跳变、材质/UV连续性；需要碰撞时制作命名清晰的简化代理，核对通道、凹凸与玩法需求，不把渲染高模直接当通用碰撞方案。
5. 保存可编辑源与当前中间导出（如任务需要），在新会话/副本重开并重新统计 bounds、三角形/顶点、对象/材质槽、LOD 与代理。脚本写入先临时保存和验证，再原子替换任务副本；修订保留原件。

## 输出与检查

交真实 DCC 源文件、所用版本/插件、操作记录、前后哈希、网格统计、视图与 `model-ID-mesh.md`；修复项注明对应对象。提示词、脚本但未运行、零字节文件不登记已制作资产。

交 `model-artist` 的 `unity-game-model-surface` 做 UV/材质，需绑定时交 `unity-game-model-rig-export`，Unity 导入 owner 为 `technical-artist`。本技能独立运行无需父文件；manifest 产物写 `.unity-game/deliverables/`，否则指定目录或 `docs/unity-game/`。DCC 重开状态与 Unity 导入状态分开，未运行的 Editor/设备检查记 `not_run`，不伪造 `.meta` 或 GUID。共享状态由 producer 更新。
