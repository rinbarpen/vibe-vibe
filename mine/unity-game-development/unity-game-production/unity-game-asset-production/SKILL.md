# Unity 资源生产与导入

## 工作位置与证据

先识别实际 Unity 项目、用户指定范围和既有产物。存在 `.unity-game/` 时读取相关状态，实际文档放 `.unity-game/deliverables/`，按需复用已存在的 templates；独立安装时使用用户指定目录，默认 `docs/unity-game/`，沿用项目现有测试和构建工具。只有实际存在时才调用 `.unity-game/scripts/unity_cli.py`，先查看其 `--help`。缺 Editor 或设备时仍可交付静态产物，但对应运行验收记 `not_run`，附具体阻塞与复现步骤；`passed` 必须有真实证据。

同一 Scene、Prefab、Animator、材质等序列化资源及其 `.meta` 只设一个写入者；同一工程的 Editor 导入、测试、场景编辑和构建串行。独立代码/规格任务可并行，依赖冻结后再集成。由 Editor 生成 `.meta`，移动时资源与 `.meta` 成对保留，不编造 GUID。已有版本和包先沿用，升级另行决策。

## 输入与规格

取得资源清单、艺术方向、目标平台/管线、尺寸/单位、预算和格式。明确本批次是 2D sprite/UI、3D mesh/material 还是环境资源；复用已有规格。确认可用创作工具与实际素材来源；概念描述、生成提示词或采购链接只是准备材料，不冒称已交付资源。

## 操作

1. 每项资源建立 ID、使用场景、规格、责任人、源文件/导出文件/Unity 路径、许可来源和状态；采购或外部上传前确认具体操作。来源不明的素材先隔离为待核对项，不标可发布。
2. 先做一个代表小样：实际创建/获取源资源，保留可编辑源与导出参数。2D 检查画布、透明边、像素密度/PPU、pivot 与切片；3D 检查单位/朝向、拓扑、法线、UV、材质槽与碰撞需求。
3. 在唯一 Editor 作业中导入，由 Editor 生成 `.meta`；按用途检查色彩空间、压缩/最大尺寸、过滤、mipmap、法线图类型、rig 与材质/管线匹配，不用同一 preset 覆盖所有资源。
4. 在实际场景光照和摄像机距离下组装 Prefab/atlas/材质，核对引用、scale、碰撞、透明排序和目标设备内存/渲染成本。占位素材显式标记；模板、空文件和失败导出不能算最终资产。
5. 小样通过后按同一可复现流程批量生产。逐项检查重名、GUID 冲突、丢引用和源文件缺失；移动资源时成对移动 `.meta`，不复制 GUID 复用到新对象。

## 输出与验收

交付真实源文件/导出资源、导入后的资源与 `.meta`、`asset-production.md` 清单、预览/场景证据和许可记录。验收同时检查视觉规格、导入无错、实际引用与目标预算；缺 Editor 时只认可源资源/静态检查，导入和场景验收留 `not_run`。

交给 `technical-artist` 检查导入/成本，关卡或唯一场景负责人装配，独立 reviewer 按艺术规范复核。批量制作中的例外和返工率返回 producer 修订产能计划。

## 3D专项接力

3D任务可将已确认规格交model-artist，实际使用unity-game-modeling及design/build/surface/rig-export子技能，通过已连接MCP、真实外部软件skill或已安装CLI制作模型。只有实际路径存在才加载；独立使用本技能时仍按本文完成自己的范围，不依赖未安装父包。源模型→导出重开→Unity导入分别验收，technical-artist负责Unity接力，独立reviewer只读复核。
