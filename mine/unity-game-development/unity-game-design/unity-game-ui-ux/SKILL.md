# 游戏 UI、输入与可访问性

## 输入

读取玩法状态、目标设备/输入方式、显示比例、已有 UI 技术栈与本地化要求。先核对项目采用的 UI 与输入包版本，保留可用实现，不为通用建议迁移技术栈。

## 交互设计

1. 从关键任务画路径：启动→进入游戏→理解操作→完成目标→失败/重试→退出；只保留任务所需屏幕。每屏列出可进入状态、动作、返回/取消和持久化效果。
2. 定义焦点与输入所有权：鼠标/触摸/键盘/手柄切换、默认焦点、导航邻接、弹窗栈、暂停菜单与玩法输入互斥。断连、按住按键进入页面、重绑冲突需有确定行为。
3. HUD 按决策时效分层；危险信息不只依赖色彩或音频，避免 UI 占据关键瞄准/路径区域。反馈明确等待、成功、失败和可恢复动作，动画与触觉不得阻塞规则状态更新。
4. 验证目标长宽比、安全区、缩放、最大本地化文本、字体回退和文本方向需求。为可调整字号、字幕、重映射、按住/切换、减少闪动/镜头运动等按实际体验定方案，不把清单勾选当成可用性证明。
5. 教程在可行动上下文中逐步呈现，并检查失败后是否能重看；关键操作不能仅在一次性说明里出现。

## 输出与验收

交付 `ui-ux.md`：任务流、页面/弹窗状态表、线框规格、焦点/输入映射、文案键、可访问性设置与验收情境。真实 UI 原型需要实际工具或项目实现；线框文字不标作可交互原型。

验收至少涵盖纯键盘/手柄主流程、触摸误触边界（若适用）、输入切换/断连、返回栈、暂停与读档恢复、最长文本和目标安全区。记录人工走查与实际 PlayMode/设备验证的区别。

`ui-ux-designer` 交状态事件与焦点规则给 `gameplay-programmer`，图形规格给 `art-director`，文案键给叙事/本地化角色，`qa-engineer` 使用验收路径测试。

默认产物目录 `docs/unity-game/`，用户可指定；存在 Unity manifest 时写 `.unity-game/deliverables/`，共享状态只由主代理维护。
