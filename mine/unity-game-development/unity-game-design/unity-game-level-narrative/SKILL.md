# 关卡灰盒与叙事结构

## 输入

读取玩家移动/战斗能力、核心循环、相机与空间尺度、目标时长、内容预算和叙事意图。有实际项目时核对控制器参数与现有 Scene；没有项目时使用明确标注的灰盒尺度假设。

## 从体验到可制作规格

1. 给关卡一个可验证学习/体验目标，画入口、挑战、反馈、休息和出口的节奏序列。新机制按引入→安全练习→组合→检验组织，而非只堆敌人或剧情。
2. 建立可达图：节点、连接、钥匙/条件、单向路径、捷径、检查点；对每种玩家能力验证主路径与可选路径，标出失败后复位位置和软锁风险。
3. 定义空间规格：可走/跳距离、视线、掩体/危险区、引导锚点和相机边界。数值从控制器或测量推导；同一布局需说明目标平台视野与输入差异。
4. 遭遇用表格描述触发条件、目标、敌人/障碍组合、结束条件、奖励与重试；叙事用事实状态、触发、条件、台词/环境线索、跳过/重看和重复触发规则描述。可跳过文本不承担唯一关键操作信息。
5. 先验证灰盒路线和节奏，再安排美术包装；资源命名、复用模块、碰撞和导航要求明确。没有 Editor 时交布局/构建规格，真实 Scene 与试玩保持未执行。

## 交付与验收

交付 `level-narrative.md`：拓扑图、区域/遭遇表、尺度依据、关键路径与支路、叙事触发状态、检查点/重置规则、灰盒验收路线。需要场景产物时按项目实际工具生成，Scene/Prefab 与 `.meta` 设单一写入者。

验收走查首次进入、死亡/重试、重复进入、顺序打乱、读档恢复、跳过剧情和缺失可选道具。记录路线时长、迷失/停顿点与实际观察；不能用理论距离冒充试玩数据。

`level-designer` 交灰盒给 `gameplay-programmer` 与 `technical-artist`；`narrative-designer` 交本地化键和触发契约给 UI/程序；`qa-engineer` 接边界路线，producer 决定超预算内容削减。

默认写 `docs/unity-game/` 或用户指定目录；有 Unity manifest 时写 `.unity-game/deliverables/`，主代理单写共享状态。
