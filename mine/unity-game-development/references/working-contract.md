# Unity Skills 执行与交接契约

## 技能、角色与实际工具

skill 提供任务步骤与判断标准；角色负责指定的工作。分派时传技能文件的实际路径，不能假设存在同名工具或某个 Unity MCP。父 skill 只是按需路由：宿主的调用、文件读取和 subagent 结果才是已发生的事实。

完整技能包可从本参考同目录的 `skill-map.json` 解析九阶段和角色映射。子技能是自包含任务说明，单独安装时不要求获取整个包，也不依赖父目录的资源。

## 环境感知

- manifest 已安装：根入口、`.unity-game/state/` 与已确认决策是事实源；模板和 CLI 按实际存在路径使用。
- 独立技能：沿用项目自己的工程、构建脚本、任务与产物目录；输出缺省为 `docs/unity-game/`，不假定 `.unity-game/` 已安装。
- 运行前确认现有 `ProjectSettings/ProjectVersion.txt`、包、输入、平台及 Editor；新项目由用户约束决定，技能包不固定版本、管线和包清单。
- 有 helper 才调用 `python3 .unity-game/scripts/unity_cli.py doctor|test|build ...`。没有 helper 时使用项目脚本或该版本官方 CLI 文档，不将缺失路径写成已执行命令。

## 并行边界

主代理维护阶段、决策和共享状态。任务包中区分实际源码/资源可写路径和报告路径；报告不代替实现。独立模块、数值和视听规格可并行；Scene、Prefab、序列化资源及设置单写，资源和 `.meta` 成对维护，同一工程的 Editor 操作串行安排。

每个依赖批次先集成再验证，后续角色读取集成后的实际输入。集成失败时保留差异、日志与失败结果，指定原 owner 修复；避免通过删除 GUID、重建工程或覆盖他人文件绕开问题。

## 交接的最小记录

- **任务与输入**：需求/假设、阶段、来源和产物版本、技能名称及实际执行者。
- **结果**：变更文件、资源取得来源、计算/实现说明，具体输出路径。
- **验证**：执行的命令和输入、实际退出码、测试 XML/Editor 日志或人工观察，`passed/failed/not_run` 分项标记。
- **缺口**：未验证平台、设备、生产能力、许可和来源不确定项，及下游可继续/等待的条件。

零测试、空日志、占位资产、没有实际样本的推测和没有渠道回执的发布均不构成相应验收通过。评审人员独立读取实际产物，不只读取实现者的结论。

## 执行与独立审查闭环

每个环节由目录内对应execute skill指导实际操作；专项任务记录原skill/owner与revision，不能以只派角色代替执行。独立game-reviewer加载unity-game-review及本阶段profile，报告绑定原始产物/证据哈希。passed且必要交付、依赖与用户门齐全才推进；changes_requested交回原skill/owner修复，新版本复审；blocked或缺独立审查的review_status=not_run均停留当前阶段。审查者只读检查，不替执行者改代码后自批。

## 游戏测试执行与证据

游戏测试由unity-game-testing按需跨阶段执行。真实普通输入和可观察断言才支持游玩覆盖，Scene检查、状态注入、模拟、计划分别标注；QA与原实现/独立reviewer分开。game_test_cli只核验已有记录和哈希，不启动游戏。缺必需用例或独立审查不推进；构建/会话改变重测复审，原始失败日志不覆盖。
