# 可追溯候选构建

## 输入与构建契约
读取候选提交、Editor/包锁定、目标平台、构建入口、签名方案和已通过的验收。记录仓库及子模块状态、生成内容来源、场景列表、Define/后端、SDK 和模块；凭据通过既有秘密管理传入，日志和报告不保存秘密值。

## 操作
1. 使用隔离工作副本和全新输出路径，从锁定输入执行项目现有构建流程。已有辅助工具时查看帮助后调用 `build --project . --target <项目平台> --execute-method <项目入口> --output <新路径>`，不猜测不存在的静态入口。
2. 同工程 Editor 串行，保存实际命令、版本、退出码、Editor 日志和 BuildReport；检查目标产物完整性，而非仅凭退出码。平台模块/签名缺失明确记录未执行原因。
3. 为文件计算 SHA-256；目录按排序后的相对路径逐文件建清单。将包、符号、必要资源及外部内容版本绑定同一候选标识，防止跨版本混装。
4. 在干净环境重复构建并比较清单；签名、时间戳或工具链导致非位相同则解释差异并记录可重建输入，不宣称字节级可复现。
5. 安装到目标设备执行启动、代表玩法、退出重进和存档冒烟；另测从当前发布版升级。保留上一发布包与匹配内容，隔离环境演练回退及其存档兼容；不默认二进制回退会恢复数据。

## 产物、验收与交接
交付构建清单、命令/日志、产物及哈希、重建差异、安装冒烟和回退证据。无真实设备或 Editor 的部分标记 `not_run`，候选构建完成不代表发布已确认。`build-release-engineer` 交给 `qa-engineer` 复验，`publishing-manager` 仅接收同一哈希候选，主代理维护版本状态。

## 运行约定
- 先读取现有项目约定、`ProjectSettings/ProjectVersion.txt`、包锁定文件和已确认平台；使用项目版本对应官方文档，不预设 Editor 版本或设备。
- 如存在 Unity manifest，使用 `.unity-game/` 既有任务与产物；否则将产物写入用户指定位置，未指定时使用 `docs/unity-game/`。共享阶段、任务、决策由主代理单写；子代理仅交付其认领文件和证据。
- 独立文档、测试设计可按文件所有权并行；同一工程的 Unity Editor、Scene、Prefab、序列化资源和项目配置由单一写者串行处理，资源与 `.meta` 成对提交。文档采用临时文件写入后原子替换。
- 运行结论使用 `passed`、`failed`、`not_run` 并附证据。缺少 Editor、设备或凭据时记录未执行范围；静态检查不替代真实运行。已安装辅助工具时可先读 `.unity-game/scripts/unity_cli.py --help`，否则沿用项目工具及对应版本官方文档。
