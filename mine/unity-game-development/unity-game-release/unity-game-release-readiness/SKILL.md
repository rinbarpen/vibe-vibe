# 发布就绪与执行控制

## 输入与判定
读取唯一候选哈希、Beta 验收、真实构建/安装结果、渠道资料、已知问题和支持安排。检查证据是否确实对应同一候选；发布清单打勾、开发者口头判断与实际运行证据分开。

## 操作
1. 整理 Go / No-Go 表：阻断问题、必要场景未测、存档/升级风险、许可/隐私缺口、渠道限制和责任人；每个风险附接受者及处理方式，不自行豁免。
2. 编写逐步 runbook，明确目标渠道/版本、操作顺序、所需权限、观察窗口、健康指标、暂停条件及回退负责人；通知文案先准备草稿。
3. 保留上一版本与匹配内容，说明存档/schema、在线服务、不可撤回商店动作对回退的限制；在隔离环境演练可行部分，数据恢复使用备份及已测试恢复流程，避免盲目降级。
4. 在完整流程的发布确认门向用户呈现候选、证据缺口、已知风险、发布及回退步骤，取得针对该候选的决定；方向或垂直切片确认不覆盖这里。实际外部上传、提交、开放及付费操作仍需明确操作确认。
5. 仅执行获确认步骤，记录字面命令/渠道响应与时间；观察触发停止条件即停止后续发布并按已确认应对流程处理。不将上传成功等同玩家安装正常。

## 产物、验收与交接
交付就绪报告、用户决定记录、执行日志、发布包哈希、监测结果及回退演练记录。缺关键证据标记 `not_run` 并保留风险，不能写已发布。独立 `game-reviewer` 审查，`game-producer` 维护决定，`build-release-engineer` 与 `publishing-manager` 执行，向运营责任人交接观察窗口。

## 运行约定
- 先读取现有项目约定、`ProjectSettings/ProjectVersion.txt`、包锁定文件和已确认平台；使用项目版本对应官方文档，不预设 Editor 版本或设备。
- 如存在 Unity manifest，使用 `.unity-game/` 既有任务与产物；否则将产物写入用户指定位置，未指定时使用 `docs/unity-game/`。共享阶段、任务、决策由主代理单写；子代理仅交付其认领文件和证据。
- 独立文档、测试设计可按文件所有权并行；同一工程的 Unity Editor、Scene、Prefab、序列化资源和项目配置由单一写者串行处理，资源与 `.meta` 成对提交。文档采用临时文件写入后原子替换。
- 运行结论使用 `passed`、`failed`、`not_run` 并附证据。缺少 Editor、设备或凭据时记录未执行范围；静态检查不替代真实运行。已安装辅助工具时可先读 `.unity-game/scripts/unity_cli.py --help`，否则沿用项目工具及对应版本官方文档。

## 阶段审查关系

本技能用于专项验收或准备评审材料；完整阶段最终由独立上下文的game-reviewer使用unity-game-review及相应阶段profile形成版本绑定结论。实现者准备的材料和自查不等同独立审查通过；修改由原执行skill/owner完成。
