# Omnisheet 的 UI 设计约束

用于新建、编辑和重排表格，以及表格衍生的报表与交互视图。将适用要求纳入统一表格规格，并传给场景子技能、格式制作人与 Omnidraw。
规则来自 vibe-coding 的 `rules/vibe-coding-ui-design.mdc` 与 `references/ui-usability.md`；在本源码仓库位于 `manifests/vibe-coding/`。本文件随技能分发，不依赖源码仓库相对路径或另装 UI 技能。已有模板、业务约定和本技能 [style-guide.md](style-guide.md) 的语义规则继续有效。

## 先服务读者的任务

- 明确谁看、要比较/录入/决定什么、完成结果是什么；已知的数据、字段与约束直接沿用。
- 当前任务的关键结果、单位、状态、异常和输入位置清楚可见；明细、来源与低频配置放到可发现的明细表、注释或详情区。关键失败和风险不隐藏在折叠区域。
- 用表头层级、行列语义、排序、对齐、间距和适用的冻结窗格建立阅读顺序，不默认把所有指标做成等权 KPI 卡片。

## 文案克制与数据保真

**Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.**

- 不给每个指标、工作表或分组加重复标题、口号和无必要描述；含糊的表头与布局先修设计，不继续堆解释。
- 保留必要字段名、单位、时间范围、口径、公式说明、数据来源、错误与风险提示。不得为视觉简洁删除数据、把未知当零，或将公式替换成硬编码结果。
- 原生可编辑表格、公式保护、实际重算、图表与宏的既有用户确认规则不因这份视觉约束改变。

## 用一套样式表达语义

- 集中定义颜色、字体、行列间距、边框和数字格式；XLSX 采用样式映射或 NamedStyle，HTML 采用 token，不逐格任意设置颜色。
- 保留输入/公式/引用等业务颜色语义，并提供文字、列名或格式提示，不只靠红绿区分。普通文字对比度至少 4.5:1，大字至少 3:1。
- 表头、明细、小计与总计有明确层级；保留精度、币种、正负值和日期含义。避免无意义合并单元格、粗重网格、装饰图表与过度着色。
- 模板与业务配色是起点，不以一套网页审美覆盖财务、科研或已确认模板的语义约定。

## 按格式验收，而非只看代码

| 格式 | 必须核对 |
| --- | --- |
| XLSX | 在实际阅读视图检查表头、行高列宽、截断、冻结/筛选和关键数值；交付打印视图时检查打印区域、分页与重复表头。不靠缩成极小字体塞入一页。公式与引用仍走实际重算校验。 |
| DOCX / PPTX 原生表格 | 检查最终页面/幻灯片尺寸中的表头、单位、对齐、跨页/溢出及可编辑性；与数据源核对数值。 |
| HTML / 仪表盘 | 在 320、768、1024、1440px 按任务重排，不整体缩小桌面表；无页面横向溢出。宽数据提供列选择、分组或可发现的明细视图，保留数据。检查实际存在的键盘、主题和空/错误/加载状态。 |

改前保留原件并对照受影响阅读任务；实际渲染/重算/操作后记录环境、尺寸或视口、命令、观察及证据。按项标记 `PASS`、`FAIL`、`NOT RUN` 或 `N/A`，不把静态阅读说成操作通过，不把 Web 断点或按钮状态强加给普通 XLSX。视觉问题返回规格或制作阶段修复。
