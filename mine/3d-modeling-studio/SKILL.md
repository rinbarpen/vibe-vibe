# 3D 精细建模工作室

把“做一个精细模型”落实为：**明确用途的建模方案 → 可编辑模型 → 多视角证据 → 针对缺陷返修 → 可重新导入的交付包**。默认以优秀商业作品/作品集为质量目标；是否达到目标通过参考对照和检查记录判断，而不是通过面数或渲染气氛宣告。

## 先确定任务，而不是先选择工具

1. 保留用户指定的软件、风格、尺寸、参考、现有模型和交付格式。修模先读现有工程及上一轮检查，定位问题，保留已通过部分。
2. 分清用户要**直接创建/修改模型**、**脚本/节点方案**，还是**技巧教学**。直接创建应实际运行宿主并查看结果；教学提供具体对象、操作、参数意图、常见失败和检查方法，避免只有软件名词。
3. 提取资产类型、用途、最终最近镜头/分辨率、物理尺度、风格、精度/变形要求、面数/贴图/显存预算与交付格式。使用 [`assets/brief.template.json`](assets/brief.template.json) 记录复杂任务；简单任务用简短说明即可。未知项标为假设，先做可逆的小样，仅对明显改变造型/成本的决定提问。
4. 用户未选软件时：通用可脚本化制作优先考虑实际可运行的 Blender；雕刻、参数曲面、服装与程序化资产按下表选专门工具。已有工程优先在原宿主延续，不擅自换软件。
5. 检查实际软件版本、宿主运行方式、API、插件与渲染能力。区分 `plan-only`（方案）、`script-ready`（脚本产出）、`host-verified`（已在宿主执行）、`visually-reviewed`（已查看结果）；按证据报告，商业软件适配指南不等于已实机测试。

## 制作闭环

### 1. 参考与结构拆解

- 把参考拆为轮廓、比例、结构连接、材料、主/次/微细节；标注每项参考对应的部件。只对实际查看到的参考作观察结论。
- 确定正面轴、尺度和原点；列出部件层级、装配/变形关系、可见背面与底部。单视图重建的遮挡部分明确为设计推断。
- 选择用途：`portfolio` / `product` / `realtime` / `animation` / `print` / `cad`。同一资产有多个用途时分别制作派生版本，不让一个网格同时承担冲突要求。

### 2. 大形校准

- 先做轮廓、比例、重心和负空间。灰模至少检查前/后/左/右/顶/底六视图及两个三分之四视角；复杂资产补关键连接、遮挡面和近景。
- 用正交图对比例，用最终镜头对阅读性；保留同机位基准。发现比例问题回到大形，不用纹理掩盖。
- 方向符合 brief 即继续；只有设计分歧、需求变化或预定高成本节点交由用户决定，常规技术问题由调查与测试解决。

### 3. 分层精修

- **主形**决定身份与轮廓；**次形**解释骨骼、装配、接缝、厚度、受力和体块；**微形**处理毛孔、刻字、织纹、磨损。按这个顺序制作。
- 用几何表达改变轮廓、明显遮挡/视差、真实厚度或制造尺寸的细节；用置换表达足够大的表面起伏；用法线/凹凸表达亚像素到小尺度细节；颜色/粗糙度不承担体积职责。
- 高模按屏幕误差、曲率和近景分配密度；保留低级控制网格、细分层级、雕刻高模、实例与程序化源。加细分前估算约 `4^级数` 的面数增长，并先测代表性部件。
- 不把通体噪声、重复螺丝、均匀倒角或一键重拓扑当成精细度。每种细节有结构或材料依据。

### 4. 用途派生与表面

- 实时：高模留档，派生低模、UV、烘焙、LOD/碰撞，按目标平台实测。动画：关节/表情边流与变形优先。工业：尺寸、公差和曲面连续性优先。打印：闭合、壁厚、间隙与切片优先。
- 保留可编辑 UV/材质，统一色彩管理、法线方向、纹理尺度与命名。先用中性光检验材质，再做表现灯光。
- 文/图生 3D、扫描或体素网格可作起点；逐项修复背面、融合部件、拓扑、UV 和表面，不直接以生成成功判为生产级。

### 5. 检查、返修、交付

1. 运行可用的几何检查；Blender 使用 [`scripts/blender_audit.py`](scripts/blender_audit.py)。检查报告通过只表示其检测范围内无阻断问题。
2. 输出多视角灰模、真实线框和关键近景；可用 [`scripts/blender_review.py`](scripts/blender_review.py) 快速生成灰模/材质辅助图，**它不生成线框、变形测试或最终艺术评审**。
3. 按质量指南逐项对照参考。记录对象、视角、缺陷、优先级、修改和回归结果；比例/结构问题先于微细节。修一处后复查相邻部件和原通过机位。
4. 保存原生文件、适合用途的交换格式、依赖贴图、预览和检查记录；在新场景/目标应用重新导入交换件，核对尺度、轴、法线、材质与层级。
5. 复制 [`assets/delivery.template.json`](assets/delivery.template.json) 填写交付清单，运行 [`scripts/check_delivery.py`](scripts/check_delivery.py)。该脚本核对文件/哈希/记录，不替代宿主打开、审美或专项验证。
6. 收尾说明软件/版本、完成状态、实测面数/材质/贴图、已检查视角、仍待验证项及文件路径。明确区分“已生成模型”“已运行检查”“已查看渲染”“已通过评审”。

## 执行底线

- 原工程只读留存或先备份；修改新版本，保留依赖和恢复方法。破坏式重拓扑、应用修改器、合并、减面、三角化都在副本执行。
- 先用本地脚本/宿主 API；可见 UI 才走 GUI 路径。发现当前会话工具与已接入服务后再调用，不预设某个 Blender/Maya MCP 已安装。
- 脚本中的参数集中定义，使用稳定对象名/集合名和随机种子（随机操作时），检查上下文和对象存在性；异常保留日志，不继续导出损坏结果。
- 高质量目标不等于所有任务强制百万面、全四边面、8K 贴图或多软件串联。缺少相应审查证据时保持 `pending`，不要填造通过记录。
