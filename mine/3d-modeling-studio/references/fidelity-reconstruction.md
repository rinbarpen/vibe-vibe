# 精确复现与专用材质重建

当用户要求“与游戏里一样”“精确还原某角色”，或任务使用已有网格、源缓冲、专用着色器时读取。普通原创建模不需要这条重建路线。

## 先选对交付路线

- **依据参考从零建模**：提供自己的控制网格、雕刻、UV 与表面；外观相似度仍须对照验证。
- **源资产导入与重建**：保留已有几何，恢复贴图、材质与场景。明确素材来源和实际贡献，不把导入的原作网格称为从零生成。
- 两者都不以面数证明相似度。角色身份依赖脸、发型、服装剪裁、装饰位置和轮廓；在身份明显不符的通用人偶上继续堆细节，不是精确复现。

用户没有截图时，先调查可用的官方角色档案、技能演示和公开实机画面；不把截图准备工作反复交回用户。区分原画、宣传渲染、二创与游戏实机；原画可以核对设计，但不自动成为游戏着色的像素基准。若公开参考分辨率低或被特效遮挡，记录限制，继续处理已明确的几何与材质问题。

## 源数据保真

仅在实际取得源网格/缓冲时执行：

1. 固定来源版本，保留不可变副本、格式描述和文件哈希。不要只记录一个会变的分支 URL。
2. 分别解析位置、索引、法线、切线及手性、UV、顶点色、蒙皮索引/权重和形态键。判断形态数据是绝对坐标还是相对偏移，骨骼索引是局部调色板还是全局索引。
3. 记录单位、轴变换、反射行列式、面绕序和 UV 的 V 翻转。用实际数据检验，不连续叠加“看起来正确”的翻转。
4. 保存源顶点 ID，在新版本保存后重新打开，独立回读每个通道；除数量外，还核对对应关系和数值误差。
5. 宿主可能压缩分裂法线或改写切线。把宿主表示误差与源数据丢失分开：必要时另存原始法线、切线和蒙皮槽属性，按实际精度设置并说明容差，不把有损宿主表示写成逐位一致。
6. 权重组不等于完整可用的骨架。缺少 bind/rest 变换时，记录为权重已保留、骨架尚未恢复，不伪称动画已验收。
7. 形态语义不明时，先按位移区域统计并在宿主逐项诊断，保留原编号/键名，把推断别名与原作名称分开。摆表情后分别检查 Basis/原始增量、声明的活动权重和实际 evaluated 网格；不要为了通过“所有权重为0”的旧检查而清空目标表情。
8. 在保留源权重上补推断姿态时，把新控制与原通道分开；混有头、身饰件的捕获组件按权重区分控制，不整块旋转。饰件投影对齐不证明关节轴心正确：复查肩、颈及支链过渡的实际边长、面积与轮廓，必要时分开锁骨、上臂和前臂并加入几何约束。实际测试控制归零及返回，推断轴心/层级不冒称原rest/bind。

## 贴图先判通道语义

- 保留原像素，按用途选择 sRGB / Non-Color；转换文件容器与改变色彩值不是同一操作。
- 颜色贴图的 Alpha 可能是 AO、材质 ID、发光或其他着色数据，而非透明度。先查看各通道与分布，再决定不透明、裁切或混合。
- Blender 中独立打包的 RGB/Alpha 使用合适的 `CHANNEL_PACKED` 解释，避免误预乘造成皮肤、金属和头发异常发暗；真实透明仍由材质明确处理。
- 同一捕获组件可能关联多个绘制阶段的纹理。文件名中的组件列表不保证它们都是该部件的材质贴图；结合 UV、分辨率、实际内容及原着色器槽位判断。
- 透明输入先查极性：同名 Alpha 可能表示不透明量，也可能作为透明分支的混合权重。沿链接确认 `0`、`1` 各选哪一支，并用已知实心/镂空区域作回归，不只检查图片自身 Alpha。
- 倒置贴图遮罩时核对采样边界：CLIP 范围外的黑色经 `1-R` 会变成实心，线性过滤还可能留下图块边框。用真实有效域/覆盖通道约束遮罩，检查孤立 mask pass 与其他视角；覆盖支持不自动等于表面透明度。
- 眼睛、皮肤、头发、金属和衣物分别校准。原色正确不代表游戏材质正确，通用 PBR 也不自动等于游戏 NPR。

## 专用渲染器与节点兼容

1. 只读检查材质库：宿主版本、引擎、节点类型、外部图像、属性名和坐标空间。出现未知节点时，暂停最终外观评审，先补齐兼容环境或明确实现缺失功能。
2. 开箱载入、场景保存、实际渲染是三个独立检查。渲染器源码编译成功也不等于材质可用；先做启动和小尺寸渲染验证，再运行角色场景。
3. 如果使用源码归档构建，检查运行必需的 Git LFS 对象是否仍是指针文本，尤其启动工程、预览工程与图像资源。按固定版本与对象哈希补齐，不用任意空文件替代。
4. 移植修复保留最小补丁、基线哈希、失败日志和通过证据。区分平台兼容修正与实际改变着色模型，避免把后者冒称原引擎等价。
5. 隔离修改节点组时，注意零引用原组可能在保存后被清除；需要留作对照的组应显式保留，并在新进程重新打开核对，而不只检查当前内存中的副本。

轮廓线节点可能只输出倒面壳或实例，不含原网格。先确认输出组成，再选择原对象修改器或共享源网格的辅助壳，避免覆盖主体或意外重复主体。保留原始顶点色驱动的粗细字段；壳是否参与投影须单独核对。若真实渲染批次在重载/切换视图时崩溃，保留已完成图及退出记录，先用独立进程补完剩余视图，再调查缓存/实例生命周期，不用渲染成功推断长期交互稳定。

## 用中间通道定位外观问题

模型发灰、背光、鼻影异常或高光缺失时，先渲染原色、法线/N·L、明暗因子、AO/遮罩和最终合成中的相关通道；不要先调曝光或重画贴图。

- 同名输入槽必须用 **socket identifier 或索引** 判断链接，例如 `A - B` 两个槽都可能显示为 `Vector`。只有显示名的节点图导出会丢失运算方向。
- 从最终 Surface/输出反向检查分支可达性：图中存在高光、深度或透明节点，不代表最终合成实际使用了它。先隔离分支做真实渲染，再恢复合成；不要为修复一个断开的输出重画贴图或重复实现已有功能。
- 求值完整的向量分支，包括减法顺序、默认向量、旋转方向、对象/世界空间与归一化。以 `Location - (Location + Z)` 为例，其起始向量是 `-Z`，不是 `+Z`。
- 身体、面部 SDF 与高光可以使用相反的光向量约定。逐分支推导其比较式与明暗极性，再用诊断图验证，不因为属性名相同就统一正负号。
- 对照材质库需要的属性：光向量可能存欧拉角而非方向，头部前向/上向可能存单位向量，眼部高光可能依赖另外的 UV 名称。按实际节点和控制脚本确认。
- 先区分可见色块的语义再拟合姿态：瞳孔、虹膜纹样、表面高光和下部反光不是同一标志；未确认的亮斑中心不作解剖点真值，避免用眼球位移去追逐材质效果。
- 轮廓配准使用当前姿态的可见边缘；正面取得的下巴点未必对应斜视轮廓，皮肤颜色边界、描边中心与几何轮廓也须分开核对。用真实新渲染复测，不只验算拟合器的预测值。
- SDF 缺陷在另一个 UV 上消失，不足以证明路由正确；检查 UV 范围、鼻/颊/耳等岛对应关系及多光向响应。通用脸型 SDF、第三方重建公式与当前角色贴图不自动配套。
- LUT/色调映射先追踪实际插入阶段：原色预处理、着色后颜色与场景合成不等价。记录输入色域、线性/sRGB、通道顺序、图块布局及最终显示变换，避免把一个可用节点误接成整图滤镜。
- 一次隔离一个因素，保留前一候选版本。中性光通过后，再恢复投影、屏幕空间阴影、发光、景深和表现光。
- 对参考做光色拟合时保留独立场景配置，不直接烘焙进中性资产。一个色块变准不代表整个材质变准；验证其他亮/暗区域和视角，并区分同一表面的对应像素与仅同类材料的外观色块。

明确记录当前通过的检查点和未采纳的试验候选；最大版本号不等于最佳结果。候选未改善参考对应的缺陷时保留其证据但不切换当前工程。

## 最终验收的边界

分开报告：源通道保真、材质路由正确、渲染运行成功、参考视觉匹配。四者不是同义词。

游戏级视觉比对至少区分几何、默认形态、姿势/表情、相机/投影、照明、轮廓线、皮肤/发丝/眼睛/金属和后处理。不同姿势或机位的图只能做有限定性核对。没有匹配参考与可解释测量时，不给虚构的相似度百分比，不用文件检查或技术审计替代“完全一致”的终验。
