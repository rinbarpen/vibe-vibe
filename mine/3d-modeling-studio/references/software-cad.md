# CAD、工业曲面与建筑软件路线

## 先区分几何体系

- **Polygon/SubD**：造型与渲染友好，控制笼/边流决定细分行为。
- **NURBS/B-rep**：曲面、边界、参数和实体用于精确设计；高密网格不是精确实体的同义词。
- **参数实体**：草图约束、特征树、装配和公差解释设计意图。
- **建筑组件**：尺寸、实例、层级与图纸一致性优先，视觉高模按镜头派生。

“渲染光滑”“曲率连续”“可加工”“可打印”是四种不同结论，分别验证。

## Rhino / Grasshopper

**用途**：工业设计、珠宝、建筑自由曲面、参数化构件。

- 先设单位与模型绝对公差，再用少量质量好的曲线建立曲面；不要用 Join 的外观成功推断缝合精度。
- Sweep / Loft / NetworkSrf / BlendSrf 按截面与连续性需要选用。控制点不是越多越好；Zebra 看高光过渡，环境映射与曲率梳辅助定位波纹；按项目约定区分 G0（位置）、G1（切向）、G2（曲率）。
- SubD 快速做自由形；对壳体连接、孔位和精密尺寸要求高的部分回到适合的曲面/实体表达，不用视觉平滑代替尺寸。
- QuadRemesh 的 target quad count 是算法目标，读取实际输出；guide curves、边界、硬边检测与对称性影响结果。自动网格转换到 SubD 后复查体积和关键截面。
- ShowEdges / Check 等检查裸边与几何有效性；闭合对象不自动证明壁厚、装配间隙或可制造。
- Grasshopper 参数集中标注单位、上下限、数据树结构；避免 flatten/graft 破坏配对关系。批量变体先测边界值，保留 `.gh` 和烘焙版本的映射。
- RhinoCommon / `rhinoscriptsyntax` 在 Rhino 运行；Rhino 8+ Python 3 与旧 IronPython 环境分别确认。使用 ScriptEditor 或实际可用的 Grasshopper 脚本组件，别混淆两套运行时。
- 原生 `.3dm/.gh`；制造交换 STEP/IGES 按接收方要求；视觉交换网格用 chord deviation、angle、edge length 控制误差，并在输出处重新测量尺寸。

## Autodesk Fusion

**用途**：产品、机械部件、可修改参数实体与装配。

- 以 component 而非散乱 bodies 组织可独立装配件。草图合理约束和标注；保留关键 user parameters 与特征依赖。
- 主体 Extrude/Revolve/Loft/Sweep → 功能孔槽/Pattern → Shell → 适合时机的 Fillet/Chamfer；顺序按设计稳定性调整，不一律把所有圆角推到最后。
- 外观曲面用 Form/T-Spline 先确定体块，转实体后检查自交、厚度和连接。交付可编辑工程时保留 timeline 的设计意义。
- 拔模、壁厚、加工方向、紧固件、装配运动与间隙由 brief 驱动；渲染是展示，不是工程签核。
- Python `adsk.core/adsk.fusion` 在 Fusion Scripts and Add-Ins 宿主执行；普通 Python 测试只能检查独立逻辑，不证明宿主实体操作成功。API 长度内部单位按官方接口逐字段核对，禁止凭显示单位假设。
- 原生 `.f3d` 或带外部关系的归档形式按实际工程选择；交付 STEP 与参数表，核对单位、圆角/薄壁和实体数量。STL 不保留参数设计。

## SolidWorks

**用途**：参数化机械设计、装配、工程图。

- 草图与特征名说明功能；基准、配置、设计表与装配关系明确。避免特征引用到不稳定的临时边导致重建失败。
- 关键尺寸、公差、材料、螺纹和装配间隙属于工程要求，不从效果图自行宣告通过。
- 造型曲面按 Boundary/Loft/Fill 等适用功能搭建；曲面拼接、曲率显示和实体有效性分别看。
- 用 Rebuild、干涉检查、剖视与质量属性交叉核对。柔性/运动装配按规定工况测试，单静态位置不代表全行程通过。
- 自动化依托 Windows 宿主 API/COM、VBA 或 .NET；宏运行前确认目标文档类型、配置、单位与 API 返回值。
- `.sldprt/.sldasm/.slddrw` 保持引用完整，必要时使用 Pack and Go；STEP/Parasolid 以接收方能力和版本为准，不承诺转换后仍保留特征树。

## FreeCAD

**用途**：本地、可脚本化的参数实体与机械原型。

- 以 Body/Part 层级管理独立实体，Sketcher 约束与尺寸表达意图，Part Design 的实体操作符合当前工作台规则。
- 对拓扑命名和跨特征引用保持谨慎；优先稳定基准与表达式，而非随机选一条新生成的边。
- 通过实际版本的 `FreeCAD`/`Part` 宿主和 FreeCADCmd 运行；`Gui` 依赖的操作不伪装成 headless 可用。
- 重算后检查 shape validity、solid count、体积、包围盒和目标参数；曲面外观检查另外处理。
- 原生 `.FCStd` + STEP，必要时导出公差与尺寸表；可视网格从实体派生并记录网格化误差。

## SketchUp

**用途**：建筑、室内、家具与组件化空间草模/精模。

- 明确群组/组件边界，把重复窗、柱、五金做 component；原始面和边留在正确上下文，避免无意粘连。
- 厚度、朝向、接缝和实尺先正确；圆弧分段按屏幕精度选取，过低分段的轮廓不靠柔化边线修复。
- 正反面一致，检查实体信息；开洞、层级变换、材质投影在导出后复查。大环境用分组、标签可见性和外部资产管理。
- 生产级角色、面部细节和动画布线转交多边形/雕刻工具，不强行把建筑工具当角色主制作器。
- Ruby API 在 SketchUp 宿主执行，使用 model.start_operation / commit_operation / abort_operation 管理事务；浏览器版、桌面版和不同套餐的扩展能力先核对。
- `.skp` 保留组件和层级；目标交换格式依版本、许可与导出器确认。重导入时检查单位、面朝向、组件实例和材质。

## CAD → 视觉高模的保形检查

1. 原生参数/曲面工程作为主档，网格作为派生，不用减面后的 OBJ 覆盖主档。
2. 根据单位、公差、最近镜头选 tessellation；在曲率高、轮廓重要处提高采样，而不是全局极密。
3. 用原曲面作基准，比较关键截面与外形；按接收端显示连续性检查法线/焊接，但不把跨硬边的强焊接当修复。
4. 参数曲面纹理需正确 UV 或可移植投射方案；程序化材质跨软件时烘焙/重建并验证。
5. 面向制造保留 STEP/实体与尺寸说明；面向展示另交可编辑 DCC 文件、材质与渲染。
