# 按体裁保留边界

这里约定写作取舍，不代替官方格式、用户项目计划或来源核验。

| 场景 | 写作重点 | 保留与核验 |
| --- | --- | --- |
| 普通文章、博客、说明 | 明确读者问题、主张、真实材料与推进顺序；避免空泛铺垫 | 原文观点与真实经历；无来源的故事不写成作者亲历 |
| 办公报告、方案、会议材料 | 结论、依据、行动与责任范围；沿模板和团队语气 | 数字、日期、单位、责任人和待决事项；正文与表格同一口径 |
| 技术文档、教程 | 条件、步骤、输入输出与实际状态 | 代码、命令、路径、版本和风险说明；完整性优先于缩短字数 |
| 学术论文 | 研究问题、方法、证据和贡献范围；保持专业语域 | 实测/推导/假设分开，引用与公式保真；科学审查和语言审阅分开 |
| 基金/项目申请 | 科学问题、拟开展内容、可行性与预期贡献 | 已有基础与拟验证假说分开；方法不是科学问题，预期成果不是已完成结果 |
| 正式审稿回复 | 从原评论恢复要求，逐条对应回应与稿件位置 | 未做工作不写成已完成；保留意见强度、实际证据与修改状态 |
| 文学/长篇中的局部写作 | 沿已有设定、视角、情节和作者风格处理当前单元 | 世界观/人物状态/时间线仍以原项目契约为准，不启动另一套小说管理系统 |

论文写作的 venue、基金申请的申报类型/年度要求、办公文件的模板以实际提供或核验的材料为准。本技能的体裁说明不是最新规则数据库。写作时需要当前外部事实或官方要求，就在所需范围检索并保留来源；没有检索则不标记已核验。

## 与专业润色引擎配合

- 普通表达使用 z-humanizer 的 general/blog/kb-doc/tutorial → unslop 路线，尊重任务要求的正式度。
- 中文学术进入 humanizer-zh-academic 的专业模式，但不把检测率承诺、标点/词频配额、随机化或刻意保留瑕疵作为本写作系统的目标；逐处检查实际表达问题，保留必要信息。
- 英文学术使用 academic-humanizer；基金可借鉴其 proposal mode 的“愿景与可行性对应”，具体章节/评审标准仍由实际申报材料决定，不机械套 NSF/NIH 到国自然。
- 只要求看问题、品鉴或审阅时输出定位意见；用户已要求改写时在原范围内执行。作者文风和事实保真优先于泛化编辑默认值。
