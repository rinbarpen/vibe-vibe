# 格式制作与多维并行 review

并行的是独立任务，不是让多个角色同时改总稿。沿用原项目的规范、任务和报告位置；下面是宿主 Agent 调度约定，不新增后台服务、自动审批器或第二套计划。只读审阅仍只读，不因发现问题自动取得改稿范围。

## 1. 格式工作从写作前期开始

先恢复本次交付格式、用户模板、章节结构、样式、字数/页数、引用体系、图表/公式和可编辑要求。期刊/会议、基金或单位的规范以实际提供或核验的版本为准，不把某种通用审美当硬性要求。没有来源的格式偏好只作建议。

| 工作 | 可以何时并行 | 结果与边界 |
| --- | --- | --- |
| 格式规范检查、模板/样式准备 | 与大纲、章节写作及图表制作并行 | 将标题层级、术语/编号、图表尺寸、题注和原生对象要求交给写作/制作角色，避免末尾重做 |
| 源稿的语法/引用/标记等结构检查 | 对已就绪章节或同版总稿进行 | 检查覆盖的源事实，不提前声称最终页数、分页、域显示或可编辑对象已通过 |
| DOCX、PPTX、LaTeX 等实际制作 | 对已接受的对应内容/素材版本各自制作 | 每个文件唯一写入者；可做阶段性候选，但输入不全时不是最终交付 |
| 多种输出 | 输入口径一致且输出文件独立时并行 | 从 DOCX/PPTX 导出的 PDF 依赖该父文件版本，不能把旧 PDF 作为新稿导出结果 |
| 最终视觉、原生功能与内容 QA | 装配、适用的域更新/重算、自检及渲染完成后 | 对当前最终文件及同版预览审阅，保留原项目要求的独立 QA 和全量覆盖 |

原生 Office 文件使用实际可用的 `office`、`office-quality` 和格式技能；排版/模板、公式、动态域、可编辑表格/图表与宏分别按用户选择验收，不重复实现格式引擎。LaTeX 沿项目正式编译路线，Markdown/HTML 沿既有渲染路线；不擅自把要求的原生文件换成截图或 Markdown。

## 2. Review 按维度分工，不默认全开

主 Agent 根据本轮目标、体裁与原项目门禁选择需要的检查。简单纠错直接最小处理；多章、图表和正式交付需要更广范围时才拆分角色。同一 reviewer 可检查相近维度，任务仍须明确，不能把“启动了很多 Agent”当检查完成。

| Review | 核对什么 | 所需输入/时机 |
| --- | --- | --- |
| 逻辑与结构 | 问题—方法—证据—结论关系、条件与主张范围、章内推进 | 候选正文及目标/大纲；默认复用随包 Content Review，系统论文按需用 Systems Paper Logic |
| 事实、证据与引用 | 主张是否有依据，原文/数据是否支持，引用对应及来源版本 | 正文和实际相关来源；只读到摘要/片段就说明范围，不报全文已核验 |
| 数据与统计 | 数字/单位、合计、舍入、比较条件、统计定义、表图与正文一致性 | 真实数据/公式/结果记录及图表；脚本数值检查不替代方法有效性判断 |
| 文风与语言 | 作者样本迁移、术语、语法、衔接与歧义 | 同版正文、适用体裁的样本/profile；没有样本不宣称违背作者声音，不用 AI 检测分数验收 |
| 图表与正文关联 | 标签/箭头/字段语义、题注、来源、稳定 ID、引用和讨论位置 | 实际图表、源数据/材料及关联正文；同版资料齐备即可审，不必等待文件排版 |
| 规范与原生结构 | 模板/标题层级、引用样式、字数/页数、对象/公式/域等选定能力 | 源稿可先做规则检查，最终对象和显示必须检查实际文件 |
| 视觉与版式 | 全页可读性、溢出/遮挡、分页、图文距离、题注/表头、字体与显示 | 最终文件和同版全量渲染；素材单图合格不等于嵌入后合格 |
| 全局一致性与领域审阅 | 跨章定义、重复/遗漏、摘要/结论与证据一致；体裁所需专业问题 | 合并后的总稿及必要证据；局部章审不能代替全局审，领域审查不由语言润色冒充 |

专业审查按实际可用技能及其边界执行，普通 Content Review 不冒称完整同行评审。外部审稿/检测服务仅在用户明确要求且满足该路线的数据处理条件时调用，不把“并行 review”理解为默认上传稿件。新数据、科学有效性或来源缺口交原研究/证据流程，不用改措辞掩盖。

## 3. 同版输入、独立只读、可核对覆盖

每轮 review 开始时，主 Agent 指定本轮快照：正文/候选稿版本、相关图表/数据/样本文风/规范版本；文件工作流记录 SHA-256 或现有版本标识。最终文件的审阅必须记录实际文件 SHA-256，并关联对应预览，不让 reviewer 读取正在被写入的可变目标。

任务包至少包含：审阅维度和范围、快照/输入路径及版本、验收要求、必要来源、实际输出报告位置、哪些未决项不在本次范围。reviewer 独立读取需要的原始材料，不只复述作者的自检结论；可以接收定位问题，但应自行核查依据。

- reviewer **只读被审正文/素材/原生文件**，只写自己的审阅报告，不直接修正文、改图或保存同一个 Office 文件。主 Agent 负责分派修复。
- 独立 QA 不由本次被审内容/素材/文件制作人自评替代；制作人脚本和自检另记。主 Agent 的汇总/总审也不等于独立 QA。
- 多个 reviewer 可以同时读同一冻结快照，并使用不同报告路径。新版本产生时先保留这一轮结果的版本归属，不将旧报告自动贴到新稿。
- 长文可按章节或页范围拆审，但主 Agent 合并实际覆盖清单，不能用 Agent 数量推断覆盖。Office 的 DOCX/PPTX/PDF 覆盖全部页面，XLSX 覆盖全部工作表的数据/公式及约定交付视图；缺页、缺表或未完成维度保持未决。
- 按源级与最终文件分别判定覆盖。章节 review 完成后仍需检查合并新增的衔接和跨章关系；最终版式 review 不能只看模板或早期示例页。

报告沿原项目/引擎格式，至少说明：reviewer 与任务、实际输入版本、检查范围/覆盖及证据、问题 ID、位置、影响/严重性、依据与最小修复、未检查项和结论。不为评分或凑问题提出无依据改写。

Content Review 原有 `pass / revise / needs_evidence / partial / not_applicable` 等状态保持原义；Office QA 沿用 `pass / pending / fail`，交付沿用 `draft / pending / passed`。主 Agent 保留原状态及范围后汇总：缺证据/部分审查不是整体通过，合理不适用的维度说明理由，不虚构为已检查。

## 4. 并行与汇合点

```text
写作/图表制作 ───────────┐   格式模板与规则准备（可并行）
                        ↓
              同版章节/正文/资产候选
                 ├─ 逻辑与证据 review
                 ├─ 数据、图文关联 review
                 └─ 文风、源级规范 review
                        ↓
              主 Agent 汇总 → 制作角色定点修复
                        ↓
        各最终文件唯一写入者装配、更新、重开自检与渲染
                        ↓
            当前文件/预览上的独立最终 QA
                 ├─ 内容/数据/原生特性
                 └─ 全量视觉/版式（可分工并行）
                        ↓
              主 Agent 按当前证据汇总交付
```

这是依赖示意，不是每次强制跑全套阶段：章节准备好就可做局部源审；独立源任务和模板准备可继续进行。最终 QA 的分工不跳过 Office 的制作自检前置门，也不拿源审报告替代最终文件内容核对。不同阶段/维度共用宿主并发容量，必要时分批，不让每章各开一套无限 reviewer。

## 5. 汇总、修复、复验与结束

1. **核对版本与范围。** 先确认各报告针对的输入和已覆盖要求；漏掉本轮必需 review、缺材料或版本不一致时，不宣布整体通过。沿已有 Writing Plan/Office 门禁登记，不另建审批流。
2. **合并问题而非投票。** 主 Agent 按位置/原因去重，保留原 reviewer 与证据。事实、用户硬约束和已核对来源优先于普通风格建议；一个有依据的核心缺陷不能被多数 pass 冲掉。冲突按来源与实际检查裁决，涉及新目标或实质取舍才交原人类决策节点。
3. **交原角色定点修复。** 正文交章节执笔者，图表交对应制作人，文件结构/版式交唯一格式写入者。公共术语、图表 ID、引用和章间关系由主 Agent 协调，不让多个 reviewer 同时应用互相冲突的改写。
4. **跟踪实际关闭。** 问题要有修复位置/版本与复验依据；“已改”消息不等于关闭。重派原问题或受影响维度检查，必要时取得独立复验；未变输入、范围未受影响的源级检查可保留其依据，不重跑无关章节。
5. **复验当前最终文件。** 任何重新保存导致最终文件 SHA-256 改变，旧最终 QA 不再代表当前文件。更新/渲染并按影响及原项目全量规则复查：可能改变分页的修改重新覆盖全部页面，数据/公式变化复查相关值与全部适用表门禁，再对新哈希给结论，不直接搬用旧 pass。
6. **按实际门禁结束。** 只有本轮全部适用要求有当前证据、没有未解决的必需修复/缺口，且原项目要求的独立 QA 通过，才按原规则交付。纯建议可记录未采纳理由，不为追求零建议反复改稿；反馈无新增证据或持续同一冲突时停止重复改写，明确未决证据/决策与下一动作，不因轮次用完改标通过。

本技能不以审阅分数、AI 检测率或“多个 Agent 都说通过”替代可定位的检查。只报告实际执行的并行工作、覆盖和验证；规则文本和安装测试不代表用户稿件已被审阅。
