# 写作中的图表协同与正文关联

图/表是论证的一部分，不是文末装饰。用于已包含图表的写作任务，或在约定范围内发现的实际需要；纯文字纠错不扩成新制作任务。这里规定交接和回流，制作仍用当前项目实际可用的专用技能，格式与来源约束沿原项目执行。

## 1. 写到哪里，需要什么

章节写作者发现关系难以用文字说明、比较需要并列、数值需要展示或已有图表应更新时，提出具体需求：

| 关联项 | 最少说明 |
| --- | --- |
| 正文位置与职责 | 哪个现有章节/段落/计划节点；需要解释的关系或支持的主张；无视觉是否更清楚 |
| 稳定 ID 与归属 | 沿用已有 ID，如 `fig:method`、`tab:comparison`；主 Agent 协调唯一制作人，多章可引用同一资产 |
| 来源与数据 | 已核对材料/数据/公式的实际位置和版本；单位、口径、缺失值、限制；来源未齐标明缺项 |
| 图表规格 | 图/表类型、必要标签/字段、图例/表头、单位、目标格式与尺寸、编辑要求、题注/替代文本 |
| 正文关联 | 首次引用、插入位置和要讨论的段落；需接回的章节任务；内部交叉引用与外部文献引用分开 |
| 结果与状态 | 实际图源/表数据/预览路径及版本、核查范围、未决项；沿用项目状态，不用“文件存在”代替验收 |

记录落在已有大纲、Brief 或计划资产记录中；小任务可直接用交接消息，不强制新建图表库。制作与引用中的显示号不是稳定 ID：插入新图后可以重排“图 2”，但原图身份不随编号变化。

**已有 auto-research Writing Plan：**复用 `composition.assets` 的资产 `node_id`、`label`、`first_reference`、`discuss_in`，以及 resolved writer packet 的相关 `assets`。章节 writer 只接收任务包；新需求交原 planner/resolver 更新、重算受影响任务包并沿原审批流执行，不修改原始 YAML、不另建资产账本。图型和编辑格式服从该项目当前规范，不以通用路由覆盖更具体的科研图要求。

## 2. 按需制作，可以和正文并行

| 需求 | 交接 |
| --- | --- |
| 真实数据图/统计图 | `omnidraw` 的数据绘图路线；使用核对后的数据、可执行代码及真实统计定义，不用图像模型生成曲线、误差线或显著性 |
| 流程、结构、机制、概念说明图 | `omnidraw` 按图型与交付格式分流；箭头、分组与标签来自当前材料，保留实际编辑源与预览 |
| 比较表、汇总表、进度/预算或结果表 | `omnisheet` 统一字段、单位、行列语义、计算/合计和注释；目标是正文表格时不额外强制生成工作簿 |
| 已有图表复用或修订 | 先核对现有文件与来源，复用稳定 ID；只重做受内容/数据变化影响的部分，不重新生成已验收的同一素材 |
| 文献原图或综述图 | 使用本项目实际检索/论文读取能力取得原图与来源记录，再交图表/格式角色处理；图像搜索缩略图不算已取得论文图 |

按技能名发现已安装入口，不沿用源码仓库相对路径。将用途、来源、版本、文风中的必要术语及最终媒介的视觉约束交给制作人；沿用 Omni 的 UI/avoid 约束，不在 z-writing 再维护一份冲突的视觉禁用清单。已有明确的图表范围直接复用；Office 中新增图表、宏或外部服务尚有决定待确认时，继续独立的正文/表格工作，不绕过原约定。

多 Agent 时，主 Agent 可把图与表分别派给制作 Agent，与不依赖它们的章节并行；小任务也可由主 Agent 直接调用所需技能，不强制一图一个 Agent。所有角色共享宿主并发上限。章节 Agent 提出需求，主 Agent 去重并确定依赖：

```text
章节写作 ──发现图/表需求──→ 主 Agent ──分派──→ 图/表制作
   │                                             │
   └─继续不依赖结果的内容           实际素材 + 数据/来源 + 检查结果
   ↑                                             │
   └────主 Agent 核对版本后回流给原章节任务──────────┘
                     ↓
        更新解释、限定、题注及引用 → 总稿装配与审阅
```

等待期间只标明具体未决位置，不把预期结果写成实测结论。原始数据没有提供时，不绘制貌似真实的结果图；按范围继续其他内容，计划示意与实际证据明确分开。

## 3. 制作人交回什么，写作者如何接回

制作人交回稳定 ID、实际输入版本、产物版本、可定位的输出，以及所做检查与未决项：

- **自绘图**：数据/计算依据、绘图代码或可编辑图源、交付预览、题注草案和必要替代文本；检查标签、箭头语义、坐标、尺度、单位、图例与最终尺寸可读性。
- **表格**：同一份已核对数据/计算模型、字段/单位、展示精度、表头/注释与表源。正文关键数值来自同一数据或结果记录，不各自手工维护一份；研究项目已有 ResearchValue 等引用机制时继续复用。
- **外部图**：原始文件/具体 panel、实际论文与版本、图号/页码/题注定位、原始资源位置、署名与已核对使用条件；不把下载的位图冒称为可编辑图源。

原章节写作者接回后，**读取真实图表及其核对数据**，而不只看“制作完成”消息。围绕图表确实展示的关系写引入、解释和必要限制；逐项核对正文中的数字/单位、比较对象、统计定义和主张强度。题注说明图表内容和条件，正文解释它对本节论证的意义，避免只复述“如图所示”。

原生 Word/PPT 表格仍交格式工程师制作可编辑表对象，不以截图冒充；图像、SVG、原生图表/形状、嵌入模型及源文件按目标格式约定交付。自绘、改编、原图引用和多源综合明确区分，不能仅加引文就把外部图变为自绘结果。

### 搜索期刊/会议综述中的图

用户要求综述/Survey/Review 图时，先由正文问题确定查找目的，检索并核对已发表的期刊/会议论文与实际版本、题名、作者、年份、venue、DOI/正式页面；读取全文/PDF 中具体图、panel 与题注，不仅使用搜索摘要。若图由综述转引其他论文，追溯原始图源及相应署名/使用条件。记录正文所需的文献键、引用方式和实际取得的文件；未核对的项保持未决。没有进行检索就不写“已核实来源”。

内部“见图 X/表 Y”是定位本稿资产，外部文献引用是说明证据/素材来源；两者都需要时分别保留。只提炼参考图版式时，也不把参考论文的科学内容或数据迁入本稿。

## 4. 双向更新，只返工受影响部分

| 变化 | 主 Agent 的处理 |
| --- | --- |
| 正文的概念、方法步骤、比较条件或主张变化 | 定位关联资产，更新必要标签/箭头/表字段或重新核查证据；不只改题注掩盖旧图 |
| 数据、计算或统计定义变化 | 基于同版来源重新生成受影响图/表，回查所有引用它们的段落、摘要/结论及题注；不复用旧值 |
| 图表的语义、数值或 panel 内容变化 | 回流给全部相关章节任务，修订解释和限制，保留其他不受影响章节 |
| 只改颜色、间距或显示编号 | 检查可读性、交叉引用与布局，正文意义未变时不重写论证或重跑研究 |
| 写作/制作期间用户改了输入 | 核对输入版本，只重派实际受影响任务；旧结果不覆盖新稿/新数据 |

状态、版本和返工记录继续放原项目已有位置。没有后台监听：由宿主 Agent 在需求发现、任务交接、结果回流和最终装配时执行核对；不要声称文件一改就会自动实时刷新。

## 5. 主 Agent 最终装配与验收

总稿及共享引用记录由主 Agent 统一写入；原生文件再交唯一格式写入者。章节和图表制作人不并发修改同一 DOCX/PPTX 或公共参考文献库。

- 图表确实存在，稳定 ID 唯一，正文引用目标正确；计划中需要的图/表没有丢失，交付范围内没有无解释的孤立资产或待制作占位。
- 首次引用、插入位置、讨论段落、题注、来源和实际产物版本相互对应；同一资产跨章引用不重复造图，不把 LaTeX 注释/示例当有效正文引用。
- LaTeX 使用项目已有 `label`/`ref` 等机制；Markdown 使用现有锚点/链接或交叉引用插件；Word 由格式工程师把稳定 ID 映射为有效书签与 SEQ/REF 等原生域，实际更新后核验显示号。不把通用的 `fig:...` 字符串原样当作合法 Word 书签。
- 正文、图、表和摘要/结论同一数值与证据口径；实际数值、合计、舍入、条件、统计解释与引用分别核对。链接存在不等于图表支持该结论。
- 编译/打开最终交付文件，按实际尺寸检查清晰度、图文距离、题注邻接、表头/分页、字体及交叉引用；沿原流程取得需要的独立 QA。素材自检不替代最终版式与语义审查。

交付统一稿、实际图表与按约定保留的编辑/数据源、必要来源与未决事项。只报告已执行的生成、检索和检查；此规范本身不是制图引擎或已完成的用户图表。
