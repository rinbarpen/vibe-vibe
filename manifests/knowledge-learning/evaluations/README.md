# 教材章节规划行为验收

这些案例用于安装本 manifest 后的**助手会话验收**，不是教材解析后端或自动模型评测。CLI 单元测试只验证安装/资源契约。手工记录助手原始输出、使用工具、文件产物和逐项结论；没有真实会话输出时不得记为模型端到端通过。

## 样例事实

- `fixtures/textbook.pdf`：5 页小型英文教材。PDF 页序 1 为封面、2 为目录；章 1/2/3 分别位于 PDF 页序 3/4/5，印刷页码分别为 1/2/3。第二章正文明确要求先理解第一章变量类型；第三章只有检查清单，没有编号练习。生成源为 `fixtures/textbook.json`。
- `fixtures/companion-slides.md`：**幻灯片提取文本样例，不是 PPTX 文件**。Slide 2 明确对应教材第二章；Slide 3 的 Checking 标题不构成与教材第三章对应的充分证据。
- `fixtures/partial-ocr.txt`：**部分 OCR 提取结果样例，不是扫描 PDF**。仅一个可确认章名；目录缺失、页码存疑。用于验收处理不完整提取结果的行为，不验证 OCR 准确率。

## 会话案例与通过标准

### 1. 上传后自动分析、保留学习会话

在空学习项目中上传 `textbook.pdf`，不先输入 `/learn --plan`。

- 先读目录/必要页面，展示 3 章地图，记录可验证的页序和印刷页码。
- 再集中询问尚缺失的目标、基础、已学范围；不追问每天几小时或完成日期。
- 在用户选择学习单元之前，`notes/atoms/`、闪卡目录不出现全书笔记或卡片。
- 回复“目标是理解整本教材；知道算术，不熟悉变量类型；还没学过”，生成双产物，格式见模板。
- 路线包含 3 个真实章节，每项有目标、定位、重点问题、真实习题或待核说明、完成标准。
- 第二章依赖第一章可以标为教材明确依赖，但需要核验正文；仅读目录时只能作为建议顺序。
- 第三章不能出现虚构的“练习 3.1–3.5”，可标未发现编号练习或另列助手自拟检查任务。
- 之后单独输入 `/learn Means --material materials/pdf/textbook.pdf`，应进入学习会话，不只再次交付路线。

### 2. 已知条件不重问、多材料不误合并

先说明“希望学会数据类型与均值；已学完第一章”，再同时提供 PDF 和配套提取文本。

- 复用目标与已学范围，仅补问缺失基础；不因为学过就自动认定掌握或跳过。
- 两份资料分别索引；Slide 2 的明确配套说明可验证，Slide 3 仅记可能相关/待核。
- 所有限定范围外章节列为范围外，不把删减误报为全书覆盖。

### 3. 缺目录、部分 OCR、页码未知

将 `partial-ocr.txt` 作为当前可用的提取结果，并说明原扫描件暂无更多可读内容。

- 索引标 partial，只保留可验证章名和已读片段；索取目录或必要页面。
- 不根据常见课程补出其他章；不把识别不清的页码写成真实页码。
- 用户要求先规划时，可给部分路线草案；基础、覆盖缺口和未知定位明确标注。

### 4. 页码体系与原有记录

对 PDF 目录所列位置和实际正文页序逐项核验，并在已有路线里写入用户记录后重新请求规划。

- PDF 页序 3 与印刷页码 1 同时保存，目录页引用不得冒充已读正文引用。
- 更新路线保留用户记录与已确认选择，不全量重提取教材。
- 不生成每日/每周课表，不自动开始持续陪学。
