# 个人学习记录与断点续学

本 manifest 通过项目 Markdown 持久保存个人学习记录，不依赖数据库、闪卡、后台监听或独立 UI。`/learn`、`/study`、`/track` 和自然语言记录请求共用此规范。

## 1. 文件与读取顺序

每个 `projects/<教材或主题>/` 使用：

- `MATERIAL_INDEX.md`：教材事实、材料 ID 与单元 ID。
- `LEARNING_PATH.md`：章节路线和完成标准，不等于用户实际进度。
- `LEARNING_RECORD.md`：学习条件、当前进度快照、个人记录和追加式历史。新建时使用 `.cursor/templates/LEARNING_RECORD.md.example`，移除未填写的示例占位，不生成示例学习历史。

开始规划或学习前先读取已存在的文件和当前对话，只补问影响当前任务的未知项；没有文件时按需创建记录，不先生成一套假日志。显式指定教材优先于当前对话选择；多个候选且无法确定当前项目时询问，不跨教材串写。`/track` 默认只读。

## 2. 记录、快照与辅导状态

### 学习条件（当前快照）

保存用户明确提供的目标、基础、已学范围和学习偏好，注明“用户提供”；缺项写“待确认”。复用信息而非反复追问，不从文件名、语言风格或回答速度推断职业、年龄等个人资料。用户纠正时更新对应字段，并在历史追加“条件变更：原值 → 新值、用户依据”。规划确认时可保存已知条件，但不要虚构一次学习会话。

### 章节进度快照

每行通过材料 ID、索引单元 ID 关联 `MATERIAL_INDEX.md` 及 `LEARNING_PATH.md`，保存当前状态、独立掌握度、证据条目、确认位置与待解决问题。无索引时可先用真实材料路径与已知章名，写“单元 ID 待关联”，建立索引后补连，既有 ID 不因路线重排随意改变。

- **学习状态**：未开始 / 学习中 / 已读 / 已练习 / 待复习。
- **掌握度依据**：未评估 / 用户自评 / 测验支持，另附具体结论及证据范围。用户自评与测验证据可并存，不伪造统一百分比。
- “已读”须有用户确认；“已练习”须有实际作答/操作，或明确标为“用户自报，未核验”。仅助手讲解可记本次活动及“学习中”，不能认定已读、已练习或已掌握。
- 测验支持记录真实题目/题源、用户实际回答或结果及反馈；无回答写“未作答”，未测写“未评估”。一道题的证据不推广成整章掌握。
- 定位优先记录已确认章/节，再按实际信息写 PDF 页序、印刷页码或音视频时间戳。用户自报位置标“用户提供”，教材位置未核验另行注明；不推算精确页码或时刻。

### 追加式日志

按运行时已知日期/时区追加条目，并采用文件内稳定、唯一的条目 ID 供更正和快照引用；日期未知则明确标“日期待确认”。没有真实时刻或时长就不填。每条按实际发生内容保存：

1. **用户原文笔记/请记住的内容**：只保存用户明确作为学习笔记、问题提供或明确要求记住的文本，用引用块保持原话；没有就不填此区。
2. **助手整理**：本次实际讲解/讨论/操作的简短摘要；具体章节讲解的知识增量自动整理到 `notes/summaries/<教材或主题>/<单元ID>-<章节名>.md`，此处链接章节主笔记，必要时链接 `notes/atoms/`，不把助手总结冒充用户原话。图文笔记与按需 PDF 规则见 `references/illustrated-notes.md`；个人原文日志不自动夹进学习笔记 PDF。
3. **练习反馈与证据**：实际作答、结果和反馈；教材题号/正文知识引用真实来源，自拟检查题明确标为助手生成。
4. **待解决问题**：用户提出但尚未解决的学习问题，可区分原文与摘要；已解决时追加解决条目并引用旧条目。
5. **当前位置与下一步**：材料及确认范围；下一步标 `[规划建议]`，不把建议写成已发生行为。

普通闲聊、完整对话转储、整段助手讲解和内部推理不自动保存。教材事实需真实来源；用户笔记、感受、自评和学习条件不强配教材出处。原文中存在错误时原文保留，核对/纠错另放助手整理区并注明来源。

## 3. 写入与更正

- 用户新增笔记/问题、确认已读范围或位置、提供作答与反馈时，在**本轮回复结束前**保存真实增量；首次建档、阶段总结、明确记录请求及导出时反馈路径，普通教学不反复列文件清单，保存失败立即说明；不等待“今天结束”等口令，也不假设能监听客户端关闭。纯查看和无学习增量的闲聊不追加学习事件；同一事件已保存后，结束小结只引用它，不重复记一次。
- 用户提出“记一下”“这是我的学习笔记”“下次记得从这里继续”等明确请求时即时保存；每次已发生的学习会话结束时保存实际活动摘要及进度，并告知路径和变更内容。
- 先读再写，只更新相关快照并追加新条目；不重建整个历史。重新导入、重规划或改变章节顺序不清空记录，也不把路线完成标准勾成已完成。
- 重复处理同一条记录请求只保存一次；补充内容链接原条目。用户更正原文时追加更正条目并引用旧条目，而不是静默替换。
- 用户明确要求删除时按指定范围删除；不要为“留痕”再次复制应删除的原文。其余历史、教材地图与路线保持不变。
- 保存操作必须实际写入成功后再回复“已记录”；只在对话中承诺不视为持久化。

## 4. 恢复与查看

`/study --next` 或自然语言“继续”先读当前辅导状态，恢复待答原题/当前提示并等真实作答，不自答推进；已答题按真实反馈后的下一步处理。旧文件没有状态区时使用最后确认位置、未解问题和日志；只有建议、没有确认起点才补问。多项目歧义时问一次，不从最后笔记推断读完或默认下一章。

`/track` 即使没有闪卡也展示章节覆盖、用户笔记/问题、助手摘要、当前位置及建议下一步。无记录明确写“暂无学习记录”，不虚构完成率。只有已知真实分母时才展示比例；实际学时只累计用户提供或计时工具记录的数据，无日期的条目不擅自归入周/月。复习统计是可选附录，不替代学习记录。

`/learn --plan` 只复用/保存学习条件并产出地图和路线，交付后停止；已有日志、原文笔记与确认位置保持完整，用户选择具体章节后才进入学习。


## 5. 当前辅导状态与无教材主题

`LEARNING_RECORD.md` 的“当前辅导状态”只保存可见信息：主题/稳定单元 ID、当前任务、待答原题（含必要选项/条件/序号）、最近实际作答与反馈、下一步及暂停任务引用。未作答标待作答，不预填标准答案或成绩；助手示范不是用户回答。新会话依据该状态而非聊天记忆续学。

明确换题时切换焦点，将旧任务暂停并保留题目/日志引用；重回旧题可恢复。含糊短回答无法对应原题时只澄清必要歧义。无教材的主题使用稳定 ID（如 T01），材料项省略/不适用，不创建假的 `MATERIAL_INDEX.md`。没有路线也可直接辅导和记录，不要求先规划。

快照有实际变化时本轮保存，日志仅追加真实活动；待答问题可保存，但不等于用户已做练习。旧记录无此区时读取已有位置和日志，后续实际状态变化才增补，不在 `/track` 或纯导出时“迁移”写文件。低打扰提示只减少前台路径展示，不取消真实保存；实际文件写入成功才报告已记录。
