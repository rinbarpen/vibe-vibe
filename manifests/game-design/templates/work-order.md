# Subagent 工作单

> 由 coordinator 从项目计划、冻结只读输入和可更新输入基线生成；执行者只处理本单范围，不改共享调度状态。机器字段以 parallel-plan / task-result 模板和 runtime 校验为准。

## 标识与派发

- 项目任务 ID / 专业包 ID：
- 角色 ID / 责任 owner：
- 当前 attempt / token / 租约到期：
- 宿主实际 worker run ID（真实 spawn 后由 coordinator 记录）：
- 模式 / 生命周期阶段 / 设计 revision：
- 目标、非目标、明确的人决定及范围：

## 输入与依赖

| 前置任务/输入 | 只读或本任务可更新 | baseline revision / SHA-256 | 获取路径 | 已完成证据 |
|---|---|---|---|---|

- 前置任务和人工门：
- 裁剪专业依赖的理由、替代输入、对下游影响：
- 缺失工具/设备/连接与可继续的独立工作：
- 写范围外只读输入变化时的暂停、依赖失效、返工和恢复点：
- 原位更新源/代码：明确负责的新版本路径、原 baseline 哈希、预期新 artifact 和后继依赖：

## 写范围与资源

- 允许写入的精确路径或目录前缀：
- 预期输出路径：
- 保持只读的输入、可在已领取写范围内修改的输入、共享状态、外部资源与其他 owner：
- Scene/World/Prefab、DCC 源、Editor/设备资源认领：
- 工作分支/工作目录与集成负责人：
- 源文件/资源 ID 配对、原件快照与回退位置：

路径认领是协作协议，不等于 OS 沙箱。跨范围需求先交 coordinator；独立工作目录不消除共享云资产或 Editor 会话冲突。

## 实际操作与验收

| 步骤/TEST-ID | 工具/版本/cwd | 实际输入/命令 | 可观察预期 | 实际输出/退出码/证据 | pass/fail/not_run |
|---|---|---|---|---|---|

- 具体执行步骤和选择理由：
- 正常、失败、取消、重载与边界用例：
- 产物存在/字节、工具执行、技术预算、视觉、引擎/设备验收分别记录：
- 修改前恢复点、回退步骤及恢复后原用例：

## 结果交回

- 报告路径 / 任务 attempt 与 token：
- 实际变更路径、原 baseline 与新 artifact 哈希、源码/资产 revision；旧审批/审查证据保持原样：
- 原始 stdout/stderr/exit、日志/截图/录制与输入：
- 作者自检结果、风险、未测项、阻断原因与下游建议：
- 任务完成前不释放的资源 / 需要 coordinator 处理的集成事项：

只读输入、依赖产物和父任务审查证据在领取/提交及各阶段重核；本任务明确领取的模型/代码原位更新保留 baseline，按新 artifact 重新验收，不把全部输入一概当成永久只读。

执行者提交不等于任务完成。coordinator 依次记录集成、独立 QA/验证与 reviewer 对同一冻结产物的结论，全部要求满足后才解锁后继。收到旧 token 或租约失效提示时停止继续写入并回报协调者，不重新领取同一任务冒充新尝试。
