# Subagent 角色与调度 (Subagent Roles & Dispatching)

在 Vibe Coding 流程中，合理调度 subagent 是提高效率的关键。

## 常用 Subagent 职责

### 1. `explore` (探索者)
- **用途**: 快速了解代码库结构、定位特定功能。
- **触发**: "这个功能在哪里实现的？", "代码库结构是怎样的？"

### 2. `code-architect` (架构师)
- **用途**: 设计复杂功能、制定重构计划、选择技术栈。
- **触发**: "我们需要增加一个缓存层", "如何重构这个模块以支持多数据库？"

### 3. Embedded implementation review
- **用途**: `implement` 内含双轴 subagent review；适用的安全检查仍由 quality gate 执行。
- **触发**: 随 `implement` 流程运行，不单独启动通用 code-review。

### 4. `shell` (执行者)
- **用途**: 执行复杂的终端操作、Git 工作流、环境配置。
- **触发**: "帮我配置一个 Docker 环境", "处理复杂的 Git 合并冲突。"

### 5. `research-analyst` (科研分析师)
- **用途**: 专门负责数据合规、实验设计建议、科研元数据规范检查。
- **触发**: "如何设计这个对比实验？", "检查数据处理流程是否符合科研规范。"

### 6. `saas-architect` (SaaS 架构师)
- **用途**: 负责多租户架构审计、租户隔离策略验证、订阅逻辑设计。
- **触发**: "我们需要增加一个租户隔离层", "审计当前的权限系统是否安全。"

### 7. `bridge-engineer` (桥接工程师)
- **用途**: 负责多端（Web/Mobile/Desktop）共享逻辑的抽象、API 契约一致性维护。
- **触发**: "如何让这段逻辑在 Flutter 和 Web 端通用？", "确保 API 响应符合多端规范。"

## 调度建议

- **并行处理**: 当有多个独立任务（如编写测试和更新文档）时，应并行启动多个 subagent。
- **链式协作**: 复杂需求按对应的 grill/spec/ticket 流程澄清后实现；review 随 implement 完成。
- **反馈闭环**: 如果评审员发现问题，应自动返回开发者阶段进行修复。
