# /structure-check

按项目现有目录治理代码结构，适用于首次采用、结构审计或模块/依赖变动。此文件是 AI 执行指南；通用宿主可直接提出“检查并维护代码结构”，不依赖 slash command 注册。

1. 读取 `architecture/structure.json` 及实际源码/构建配置；不存在时参考项目根目录的 `references/code-structure.example.json`，调查后编写项目自己的结构契约和架构说明。不要复制示例目录去覆盖业务项目，不要求安装 CodeGraph。
2. 明确源码范围、排除的生成目录、模块职责和唯一所有权、导入别名/外部前缀、允许依赖、公开文件/包、入口与文档。保留语言原生布局。行数预算只在项目有依据时配置。
3. 运行 `python scripts/check_structure.py check --root .`，如采用已审查债务，加 `--baseline architecture/structure-baseline.json`；核对 JSON 的状态、覆盖范围、阻塞和新/旧问题。检查器不会执行源码、联网、安装工具或修改文件。
4. AI 先解决解析/证据缺口和实现问题，按需获取原生依赖报告，运行语言原生 lint/build/test。新增业务取舍/不兼容接口或接受新风险才请求人决定，绑定契约、候选及当前源码版本；未答复不更新许可或假称已批准。
5. `snapshot` / `baseline` 子命令只在 stdout 返回候选。首次采用或有意变动时核对退出状态、对比原件和架构文档，再用临时文件 + `os.replace` 保存选定候选；baseline 不自动重生。不做“每次检查前先重置快照/基线”的 CI。
6. 重跑检查和相关测试，保留前后证据、债务列表、结构 diff 与实际退出状态。取消/失败按本次备份恢复拥有的文件，重验后说明结果。

验收：契约与实现/文档一致；无新违规或旧债务增长；快照无漂移；检查覆盖/限制可见；原生构建和相关测试真实完成。独立审查沿用 `implement` 已有轴，不增加强制代理流程。
