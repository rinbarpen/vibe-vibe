# /update-docs [目标或任务]

默认聚焦当前变更影响的首页或文档，不全库扫描、套八段模板或生成一堆完成报告。
所有路径以项目根目录为基准；写作约定见 `references/readme-guide.md`。

## 执行

1. 确定读者、要完成的任务和现有入口。用户要求改善可读性时，先检查信息顺序，不先加更多说明。
2. 对照实际代码、配置和命令帮助核实相关事实；只调查必要范围，不把静态扫描说成已运行验证。
3. 在原文副本上修改：README 保留首个使用路径和任务入口；参数、完整清单、架构与开发记录放到合适的详细页，保持可发现链接。
4. 需求已确认的文字和组织调整直接写入并检查。只有产品语义、支持范围或新约束的冲突才请人决定；未回答不视为同意。
5. 沿初次读者路径复查：是否清楚项目用途、前提、执行目录、第一步和预期结果；是否不靠猜测跳转；必要限制是否保留。
6. 运行只读检查，修复实际结构错误；长段落或长表是复看信号，不是自动判定文档差。核对已存在的其他语言版本，保留回退与实际验证结果。

## 只读检查工具

```bash
python3 .cursor/commands/update-docs/update_docs.py --root . README.md
python3 .cursor/commands/update-docs/update_docs.py --root . --format json README.md docs
```

显式路径可以是文件或目录；目录只读取其中的 Markdown。缺文件/越界输入退出 2，围栏或本地链接错误退出 1，否则退出 0。工具不修改文档，不读取项目源码，不联网检查外部链接，也不证明命令可执行或文档已经好读。

新增文档或移动内容后，检查旧入口、相对链接和锚点。不要为了过检查而删除必要信息、自动批准产品承诺，或把所有提示消成空文档。
