# UI 易用性与操作验收契约

适用于 Web App、桌面 WebView，以及对应平台测试工具可覆盖的界面变更。
优先复用项目设计系统、已有组件与测试；不强制新增设计技能、额外访谈或状态账本。
本契约指导 AI 编辑代码和验收，不是可视化拖拽编辑器，也不是用户研究。

## 1. 入口与基线

- 从当前请求、页面与现有约定提取主要用户、主要任务、关键结果及约束；信息已确认时直接执行。
- 按变更范围选取受影响任务及状态，不把所有小修改升级为全站改版。
- 改动前记录任务路径、重要信息位置、操作/往返步骤、适用的重复输入和截图，作为 baseline。
  新页面没有历史版本时说明「新页面，无历史基线」，按任务验收，不虚构改前数据。
- 验收目标来自具体任务和项目标准。点击数、首屏容量和信息密度没有跨项目统一阈值。

## 2. 信息优先级与布局

| 层级 | 内容 | 呈现要求 |
| --- | --- | --- |
| 立即可见 | 当前任务必要的状态、关键结果、异常、下一步入口 | 在相关任务区域直接找到，具有清楚层级；关键异常不折叠隐藏 |
| 按需查看 | 支持决策的细节、历史记录、解释 | 清楚标识展开或详情入口，查看后保留任务上下文 |
| 高级配置 | 低频、专业或内部实现选项 | 按需展开，有默认值和影响说明；不阻塞常见任务 |

- 同一任务区突出主要动作，降低次要动作和装饰的视觉权重；不要把所有信息做成等权卡片。
- 使用字号、语义、位置与间距共同建立层级，不只依赖颜色；保留可读性和键盘可达性。
- 简洁不是删功能或隐藏风险，也不是缩小文字、无限留白或把必要信息拆到多个跳转里。
- 专业高密度场景按任务分组，保留必要上下文；移动端按任务重排，而非缩放桌面页面。

### 文案克制

**Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.**

- 不为每个卡片、标题或区域添加无必要的副标签、重复说明或 slogan 式文案。
- 用分组、位置、对齐、层级和清晰控件表达用途；优先修正含糊的布局和交互，而非靠更多说明掩盖问题。
- 必要的表单标签、无障碍名称、错误与风险提示、单位和帮助说明保留；按用户任务判断必要性，而非一刀切删除文字。
- 走查时检查每条次要文案是否增加必要信息，重复或仅装饰的删减/合并后，仍应理解页面并完成任务。

## 3. 设置与表单

- 按用户目标组织，常用项靠前、高级项按需展开；相关条件字段在适用时展示。
- 提供合理默认值、当前有效值、必要的作用域/生效时机/重启要求，以及简短影响说明。
- 明确自动保存或显式保存；区分未保存、保存中、成功和失败，失败保留合法输入并给出重试入口。
- 保存后刷新或重新进入，核对需要持久化的值及真实状态；成功提示不替代持久化验证。
- 错误靠近对应字段，避免内部术语；重置、取消和破坏性操作说明影响范围，遵守项目既有确认约定。

## 4. 任务验收与证据

使用 `/frontend-check usability` 做渲染界面的任务走查，使用
`/frontend-check interaction` 执行实际操作与结果断言；全量检查为 `/frontend-check all`。
这些是 AI 命令契约，不自动创建项目脚本、安装浏览器或保证工具已存在。

| 检查 | 期望结果 | 适用证据 |
| --- | --- | --- |
| 主要任务 | 找到入口、完成操作、看清结果和下一步 | 实际操作步骤、状态断言与相关截图 |
| 设置保存 | 保存与实际生效一致，刷新/重新进入后保持 | 保存前后值、持久化或集成断言 |
| 异常与边界 | 加载、空、慢响应、错误、非法输入、重复提交等有明确反馈 | 确定性 fixture、错误断言、失败 trace/截图 |
| 取消与重试 | 不意外丢失合法输入，不重复产生外部副作用 | 状态与适用的请求/数据断言 |
| 可访问与适配 | 相关小屏和键盘操作仍可完成任务 | 视口、焦点/键盘记录与工具输出 |
| 改前/改后 | 关键入口和信息更清楚，操作成本变化可解释 | 基线对比，不伪造用户耗时或成功率 |

沿用 ui-testing 的语义定位、自动等待、测试隔离和失败证据原则；无需为此另装完整 manifest。
依赖已有项目脚本、实际启动命令和 URL；优先隔离的本地或测试环境，发布前按需要补 staging 集成。
有真实数据写入时使用隔离账户和数据并清理。模拟 API 的浏览器测试只证明客户端行为，
不能作为真实后端持久化或原生桌面/移动能力的通过证据。

在已有测试报告或 PR 记录里保存以下字段，不要求新增一份状态数据库：

- 范围：页面/任务、版本或 diff、环境、视口、前置数据、真实/模拟依赖及验收目标。
- 基线与改后：信息层级、任务路径、步骤/重复输入变化，以及适用截图。
- 执行：精确命令或可复现操作、输入、期望结果、实际输出与退出状态；证据路径。
- 结论：逐任务/模式标记 `PASS`、`FAIL`、`BLOCKED`、`NOT RUN` 或 `N/A` 及原因。
- 未验证项、后续所需环境或人工输入，以及必要的回退入口。

缺工具、缺服务或未执行浏览器操作时明确记录，不以静态代码审查替代操作通过。
`all` 仅在所有适用且要求的模式通过后才算全量完成；局部通过不等于全量通过。
AI 走查结论与真实用户反馈分别标注，用户测试的结果只在实际执行后报告。

## 5. 执行、人工决策与回退

1. **AI 执行**：记录基线 → 调整信息结构与设置 → 实现 → 运行受影响任务。
2. **AI 验证**：操作失败返回实现；易用性问题返回布局/设置设计；修复后重跑相关验证。
3. **依赖等待**：调查缺失的服务、工具或 fixture，保存阻塞原因；条件具备后从操作验证恢复。
   只有需要新增预算、凭据、目标或约束决策时再请人处理，不把每个技术问题都推给人。
4. **人工决策**：目标/业务语义变化、取舍冲突或预定义高影响门才触发。
   提交当前版本/diff、证据、可选方案与影响。未回答时等待相关动作，不推定同意；独立任务可继续。
   同意/调整后核对版本和真实状态，从基线与验收范围节点继续；实质变化重新取得有效决定。
5. **回退**：修改前保留原版本和适用数据快照。取消或决定撤销时只恢复本次拥有的改动，
   数据变更沿用项目回退入口，不覆盖他人新修改；实际执行恢复并检查关键任务，记录「已回退」与验证结果。
6. **交付**：输出变更摘要、验证范围/证据与未验证项；取消后的已验证回退与功能交付分别标明。

## 6. 可复现工作流

[查看 SVG](ui-usability-workflow.svg) · [编辑 JSON 源](ui-usability-workflow.json)

图表达规则，不表示节点已执行或人工已批准。沿用已有的通用标准库渲染器，
从 manifest 目录或安装后的项目根目录运行：

```bash
python3 scripts/render_codegraph_workflow.py --source references/ui-usability-workflow.json --output references/ui-usability-workflow.svg
python3 scripts/render_codegraph_workflow.py --source references/ui-usability-workflow.json --output references/ui-usability-workflow.svg --check
```

`--check` 只读：图缺失或漂移返回 1，无效源或边引用返回 2；正常一致返回 0。
安装/更新只分发本契约、图源、SVG 与共享渲染器，不扩大为任意 references/scripts 复制。
